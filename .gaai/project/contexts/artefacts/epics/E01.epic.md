# Epic: PWA shell

## Purpose

An athlete can open HuskyHealth from a link, add it to the iPhone Home Screen, and open it again with no network. This is the installable, offline-capable frame every later feature lives in, and it ships with the Content-Security-Policy that locks the app's network egress from day one (PRIV-9). Feature F1; build-order step 2.

---

## Scope

- `web/_headers` exactly as in plan 10.3b; `web/index.html`, `web/manifest.webmanifest` and `web/sw.js` per plan 10.4.
- `web/sw.js` SHELL lists only the shell's own files (index.html, CSS, app entry JS, manifest, icons). The 10.4 list is the eventual target. Each later epic adds the files it needs offline to SHELL and bumps the cache name in the same change (R-1).
- Placeholder icons: 192, 512 and apple-touch. Original artwork only (FE-5).
- An About line that shows the deployed commit from `/version.txt`.
- No inline CSS or JS (FE-1).
- Once on Cloudflare Pages: `curl -sI` shows the CSP; it installs on iPhone from the staging preview; it opens in airplane mode.

Sources: `.gaai/project/contexts/memory/project/infra-pwa.md` [PLAN 10.4], `.gaai/project/contexts/memory/project/infra-deploy.md` [PLAN 10.3b], `.gaai/project/contexts/memory/project/architecture.md` [PLAN 5.1, 5.3].

---

## Out of Scope

Everything else, including: engine, parsers, `features.js`, `db.js`, `ascii.js`, the ASCII UI and palette, References, import, voice, `r.html`, vendored libraries, the relay, and connecting the Pages project (Ved does that; SAFE-3).
