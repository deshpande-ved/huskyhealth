# Epic: ASCII UI and References

## Purpose

An athlete opens HuskyHealth and sees today's training call, their HRV band, 60 days of load and their fitness and fatigue, drawn as ASCII on the phone. Every number links to the published method behind it. Their data is kept on the phone as summaries only, and one tap forgets it. This is what makes the engine's output usable and the science checkable (features F2 and F5). It also adds the end-to-end, airplane-mode run (F6) that proves the whole import → engine → UI path works with no network.

---

## Scope

Spec: `huskyhealth-runbook.md` Part E, epic E04 (sources: plan 4, 5.5, 7.3, 10.4 `db.js`). Acceptance list, binding:

- `ascii.js` tests pass (`RAMP` has 70 characters, gauge, bar)
- from fixture features: the call banner, HRV gauge, 60-day calendar and fitness/fatigue plot render
- every figure is `role="img"` with an `aria-label` carrying the numbers; a Plain view toggle exists
- the References page has a card per 7.1 row, linked from every metric
- IndexedDB stores features only; **Forget everything** clears it
- Rosé Pine colors come from CSS classes; it's usable at 44 columns

Additions beyond the runbook epic text:

- F6 "End to end + airplane-mode run" (Session Brief D-8, DEC-18: no feature silently dropped): real import → engine → UI on the installed PWA with zero network requests in airplane mode. Phone checks are manual (Ved); a local automated no-network check is the Delivery part. Stories: E04S07.
- Remaining screen items (Ved's round-1 decision R-3, DEC-18): zone bars, monotony and load-spike flags, the other 7.4 data-gate messages, import progress bar, typed effort entry (E04S08, E04S10), and the ASCII husky mark with icons from it (E04S09, cuttable). These are beyond the runbook acceptance list above.
