# Epic: Garmin and validation

## Purpose

Two outcomes (features F14, F15):

1. **Any Garmin owner can use HuskyHealth.** They drop their `.fit` activity files into the app and get load, fitness and fatigue, decoded on the phone with Garmin's own FIT SDK. No Garmin login, ever (DEC-4); no network during import (DEC-2, PRIV-1).
2. **The engine's numbers are checked against an established tool.** The same `.fit` files go through GoldenCheetah; its CTL/ATL curves are compared with our fitness/fatigue, and the correlation is shown on the References page (DEC-22, plan 7.4 layer 2). This backs the "published methods" claim (DEC-6) with evidence.

---

## Scope

Spec: runbook Part E, epic E09 (sources: plan 6.2, 6.4, 7.4 layer 2, held in the memory files below). Binding acceptance list:

- `.fit` import through the vendored `@garmin/fitsdk` produces features offline.
- Sports are mapped; unknown → `other`.
- The GoldenCheetah comparison steps are written for Ved to run by hand.
- The resulting correlation is shown on the References page.

Plus the constraints from the sources, rules and brief:

- H-1 (unverified): `@garmin/fitsdk` can be vendored for offline in-browser use, under a licence that allows it in a public repo. The first story checks this and STOPs if not. No CDN (PRIV-1).
- Collect less (PRIV-3, DEC-13): the FIT decoder reads only an explicit field allowlist; GPS positions and device names are never kept.
- No `.fit` file is ever committed (SAFE-1; the pre-commit gate blocks `*.fit`). Tests build synthetic FIT bytes in memory.
- T-1: the GoldenCheetah run and the correlation number are "manual (Ved)". Delivery builds the steps, the comparison scripts and a References card that shows a value Ved supplies. No GoldenCheetah (GPL v2) code or files enter the repo.
- Garmin-only users have no overnight HRV, so readiness shows "not enough data"; load still works (plan 6.2).

---

## Out of Scope

- Logging into Garmin Connect, Garmin APIs, or any scraper (DEC-4).
- Garmin's full account export (arrives by email; too slow).
- Garmin data arriving through Apple Health sync: that is just Apple Health records (E03).
- Effort/RPE from FIT files; Garmin sessions have no user effort, so session-RPE stays empty for them.
- Changing engine formulas to match GoldenCheetah. The cross-check reports agreement; it does not tune the engine.
- Any Rust/WASM decoder (DEC-12).

- `node --test` passes on in-memory synthetic FIT data: features match, sports map, unknown → `other`, no GPS or device strings in the output.

- manual (Ved): a `.fit` file imports on the installed PWA in airplane mode.
- manual (Ved): the GoldenCheetah run gives a correlation, and the References card shows it.
