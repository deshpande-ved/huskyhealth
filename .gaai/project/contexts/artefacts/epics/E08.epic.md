# Epic: Presidio and proof

## Purpose

Users and judges can verify, with reputed tools, that nothing identifying leaves through the relay. Microsoft Presidio acts as an independent PII tripwire on every outbound path, and paste-ready proof scripts show single-use tokens (replay → 410), a smuggled device name being rejected, and a read-only relay container that kept no tokens. A HIPAA Safe Harbor table puts the claims next to a recognized standard on one slide. (Features F8, F20.)

---

## Scope

- Presidio PII scan on the relay: keys and string values of incoming JSON, the outbound prompt, and Claude's brief (not number arrays). Custom `DEVICE_NAME` recognizer; `DATE_TIME` excluded. Any finding blocks the request. Findings are logged and audited as counts / entity types only, never content.
- Relay dependencies added here, not in E05: E08S01 adds `presidio-analyzer` to `relay/requirements.txt` and the `en_core_web_sm` download line to `relay/Dockerfile`.
- Synthetic fixtures: a clean brief and a smuggle brief (device name hidden in it).
- Proof scripts: `scripts/replay.sh`, `scripts/smuggle.sh`, `scripts/pi-proof.sh`.
- Slide-ready text: HIPAA Safe Harbor 18-identifier table and the threat model.

Acceptance (binding, from the runbook):
- the smuggle fixture → 422 with `schema_ok=false` and `pii=["DEVICE_NAME"]`
- 0 findings on fixture briefs
- `replay.sh` → 200 then 410 (manual (Ved): against the live relay)
- `pi-proof.sh` → `readonly=true mounts=0`, 0 changed files, 0 token hits (manual (Ved): on the Pi)
- the Safe Harbor table text is ready for a slide

---

## Out of Scope

- The relay itself, `/v1/token`, the strict `BriefIn` schema, token minting/burning, compose/Dockerfile and the read-only container (E05).
- Gradium `/v1/speak` and `/v1/listen` (E07); the speak text is Claude's brief, already scanned here.
- Presidio's anonymizer for Ask HuskyHealth (F17) and the ARX risk analysis (F18) (E10).
- mitmweb egress capture setup (E05).
- Running scripts against the live relay or on the Pi (manual, Ved).
