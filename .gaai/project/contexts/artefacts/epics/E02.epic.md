# Epic: Engine

## Purpose

Give the athlete training numbers they can trust: load, fitness, fatigue, form, monotony and a HARD / EASY readiness call, each computed on the phone from published methods (or clearly labeled as ours), each carrying its source. The engine is the "rules decide" half of CLAIM-3; the UI (E04) and the AI brief only display and explain what it returns.

Feature F4. Spec: `huskyhealth-runbook.md` Part E, "E02. Engine".

---

## Scope

- `web/js/engine.js`: pure functions for every row of the 7.1 table (zone minutes, TRIMP, session-RPE, fitness / fatigue / form, monotony, readiness band, data check, baseline length, load spike, VO2 max trend, sport-specific view).
- Input is the features JSON contract (`v: 1`) from plan 6.5; output values each carry a source (method name + version + status + References id), per FE-2.
- The 7.4 layer-4 data gates (HR sample density, max HR may be low, not enough HRV data, rate your effort).
- Tests with `node --test "tests/**/*.test.{js,mjs}"`: a hand-worked test for every 7.1 row, and every 7.4 layer-3 scenario. The root `package.json` (`"type": "module"`, `"test": "node --test \"tests/**/*.test.{js,mjs}\""`) is created here, in E02S01 (R-4d), and reused by later epics.
- Purity: `engine.js` has no DOM access, no network access and no imports (PRIV-1).

---

## Out of Scope

- The References page and any UI or rendering (E04).
- Parsing Apple Health or Garmin data, and building the features JSON (E03, E09).
- The GoldenCheetah reference cross-check, 7.4 layer 2 (F15, E09).
- The AI brief and anything sent to the relay.
- Any metric not in the 7.1 table (HuskyScore, sport multipliers and invented thresholds stay removed, DEC-6).

## Success Metrics

- `node --test "tests/**/*.test.{js,mjs}"` is green.
- Every 7.1 row has at least one hand-worked test (numbers worked out by hand in the test comments).
- Every 7.4 layer-3 scenario passes: taper raises form; doubled week sets the load spike and drops form; 7 identical loads with no rest flag monotony; HRV 1 SD below baseline for a week gives "easy"; 3 HRV readings in a week suffice, 2 don't.
- `engine.js` passes the PRIV-1 / no-DOM grep check.
- Every engine output value carries `source` (FE-2).

## Dependencies

- E01 (E01S03): `web/sw.js` and its `SHELL` list. E02S01 adds `/js/engine.js` to it (R-1), so the offline install keeps working.

The engine otherwise runs on synthetic fixture features, with no dependency on E03 (E02S04 reads `hr_sample_ok` from fixtures, R-4c).

Downstream (for the main session): E03's `features.js` computes per-workout zone minutes and TRIMP with E02S01's functions; E04's References page and metrics use the source ids defined in E02S01.
