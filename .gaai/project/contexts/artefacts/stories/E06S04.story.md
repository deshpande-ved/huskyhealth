# Story: Shortcut build sheet

## User Story

**As** Ved (and later any athlete),
**I want** a step-by-step sheet for building the **HuskyHealth Sync** Shortcut and its automations,
**so that** I can set up auto-sync on my phone, and the relay accepts only the exact payload the sheet describes.

---

## Context

Claude Code can't build Shortcuts. Plan 5.4, "Each sync" steps 1–3. Deliver `docs/shortcut-build-sheet.md` (public repo) and a strict payload schema on the relay.

The Shortcut keeps `state.json` (last check time, end time of last synced workout) in On My iPhone → HuskyHealth. Last check under 15 min ago → stop. *Find Health Samples*: workouts after the last synced end time, limit 1; none → save check time, stop. Only with a new workout: build the payload (new workouts with heart rate, last 3 days of resting HR, HRV and effort), `POST /v1/drop/<box>` with the write secret, and update `state.json` on success.

H-5 (unverified): the triggers App → Is Opened, Apple Watch Workout → Ends and Charger → Is Disconnected exist with those names.

---

## Acceptance Criteria

- [ ] AC1: `docs/shortcut-build-sheet.md` lists every Shortcut action step by step: pasting the pairing code once, reading and writing `state.json`, the 15-minute throttle, the limit-1 new-workout check, building the payload, the POST with the write secret, and updating `state.json` only on success. Checked by `grep -n` for these exact headings: `## Paste the pairing code`, `## Read state.json`, `## 15-minute throttle`, `## Check for a new workout`, `## Build the payload`, `## POST the drop`, `## Update state.json`.
- [ ] AC2: the sheet lists the triggers App → Is Opened (several everyday apps, Run Immediately on, Notify When Run off), Apple Watch Workout → Ends and Charger → Is Disconnected, and says the network is touched only when there is a new workout. Checked by `grep`.
- [ ] AC3 (compliance, error-handling): the payload JSON schema is in the sheet and enforced by a pydantic model `SyncDrop` with `extra="forbid"` on `POST /v1/drop/<box>` before `seal()`; every nested pydantic model also sets `extra="forbid"`, and the sheet's example JSON validates against `SyncDrop`; it has no device names, source names, GPS or calendar dates (times are second offsets from send). pytest: a synthetic valid payload → 204, an unknown field → 422, a `device` field → 422, and the 422 body never echoes input (PRIV-6).
- [ ] AC4 (compliance, SAFE-2): the sheet is public-safe: the only host is the public relay origin on port 10000, the write secret appears only as a placeholder, and `grep -nE "([0-9]{1,3}\.){3}[0-9]{1,3}|ssh |@[a-z0-9-]+\.(com|edu)" docs/shortcut-build-sheet.md` returns nothing.
- [ ] AC5: manual (Ved): H-5 check. On his iPhone, Ved confirms each trigger exists under that name. Any trigger that doesn't exist is recorded in the sheet as "not available on iOS <version>"; don't invent a substitute. If App → Is Opened is missing, STOP and report (DEC-21 depends on it).
- [ ] AC6: manual (Ved): Ved builds the Shortcut from the sheet; opening Messages twice within 15 minutes with no new workout makes no network request and the Shortcut run stops at the throttle step. Checked with `curl` GET (read secret): after the two throttled opens it returns 404; after a new workout it returns one drop.

## Notes

- Payload times are second offsets from send, and no calendar dates are sent (R-4g). E06S03 places them using the relay's `age_s`.
- The sheet says plainly: the Shortcut holds the write secret; don't share your copy (5.4 caveat).
- The sheet keeps at least one HR sample per 15 s. If the payload with 3 days of HR would exceed 64 KB, the Shortcut drops the oldest workouts to stay under the cap; the cap is not raised.
