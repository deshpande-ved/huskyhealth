# Story: Strict BriefIn schema and single-use RAM tokens

## User Story

**As an** athlete who asks for a coaching brief,
**I want** the relay to accept only a fixed list of numbers and to use each permission token exactly once,
**so that** nothing else about me can get through and no request can be replayed or linked.

---

## Context

The relay's privacy rests on two small pure modules: the pydantic allowlist (`BriefIn`, `SpeakIn`) and the RAM token store (`mint`, `burn`, `digest`). Both are given verbatim in the memory sources; this story writes them and proves them with pytest before any route uses them (DEC-10, PRIV-2, PRIV-7).

---

## Acceptance Criteria

- [ ] AC1 [error-handling]: Given the schema, when `BriefIn.model_validate_json` gets an unknown field, a string where a number is expected (`"47"`), an out-of-range value, a `zone_pct7` of length 4, a third flag, or a flag other than `monotony` / `load_spike`, then it raises `ValidationError`; the synthetic valid sample in `tests/fixtures/briefin-sample.json` validates. Checked by `pytest tests/relay/test_schema.py`.
- [ ] AC2: Given `SpeakIn`, when `text` is empty, over 600 characters, or extra fields are sent, then it raises `ValidationError`. Checked by pytest.
- [ ] AC3 [compliance]: Given a minted token, when it is burned twice, then the first `burn` returns `True` and the second `False` (single use, PRIV-7). Checked by `pytest tests/relay/test_tokens.py`.
- [ ] AC4 [error-handling]: Given a token, when it is burned with the wrong `kind` or after its TTL (monkeypatched `time.monotonic`), then `burn` returns `False` and the token is gone from `_TOKENS` either way. Checked by pytest.
- [ ] AC5 [compliance]: Given a speak token minted with `bound=digest(text)`, when it is burned with the digest of a different text, then `burn` returns `False`; with the same text it returns `True`. Checked by pytest.
- [ ] AC6 [compliance]: `relay/tokens.py` keeps tokens only in a module-level dict guarded by a `threading.Lock`, uses `secrets.token_urlsafe(16)`, and writes nothing to disk: `grep -nE "open\(|write|pickle|shelve|sqlite" relay/tokens.py` returns nothing.

## Notes

- Copy `BriefIn`, `SpeakIn`, `mint`, `burn` and `digest` exactly as in the memory sources; do not add fields or loosen `extra="forbid", strict=True`.
- `tests/fixtures/briefin-sample.json` is synthetic (made-up numbers, no dates, no names). E05S05 and E05S07 reuse it as the JS/Python contract fixture.
- `tests/relay/conftest.py` puts `relay/` on `sys.path` so tests import `schema` and `tokens` the way gunicorn does (`app:app`).
- `relay/requirements.txt` holds only what E05 needs: `flask`, `gunicorn`, `pydantic>=2`, `anthropic`. E05 adds no Presidio and no cryptography: E08 adds `presidio-analyzer` (and the spaCy model step), E06 adds `cryptography`. `relay/requirements-dev.txt` is `-r requirements.txt` plus `pytest`.
