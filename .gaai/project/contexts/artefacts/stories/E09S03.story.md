# Story: Import .fit files in the app, offline

## User Story

**As a** Garmin owner,
**I want** to pick one or more `.fit` files in HuskyHealth and see my training,
**so that** I can use the app with files from Garmin Connect's "Export Original" or my watch's `GARMIN/Activity` folder, even in airplane mode.

---

## Context

E09S02 gives a pure `fitToFeatures()`. This story adds the thin Web Worker from plan 6.4 (`web/js/parse-fit.worker.js`), lets the import UI (E04) accept `.fit` files next to `.zip`/`.xml`, stores the result the same way as the Apple path (features only, in IndexedDB), and adds the new files to the service-worker `SHELL` so the import works offline. Garmin users are never asked for a Garmin login (DEC-4).

---

## Acceptance Criteria

- [ ] AC1: The import file picker accepts `.fit` (multiple files) as well as `.zip`/`.xml`. `.fit` files go to `parse-fit.worker.js`; the features it returns are saved through `db.js` exactly like the Apple path (features JSON only). Checked by: `node --test tests/import-route.test.js` on the routing function (file name/extension → worker), plus manual (Ved) below.
- [ ] AC2 (error-handling): The worker posts progress per file (`{ progress: i, total }`) and a final `{ done, features, skipped }`. If every file is skipped, the UI shows "No readable .fit files" (built with `textContent`) and stores nothing. Checked by: `node --test tests/import-route.test.js` on the pure `importOutcome(msg)`, which returns the "No readable .fit files" message and `store: false` when every file is skipped.
- [ ] AC3 (compliance, PRIV-1): No network on the FIT path. Checked by: `grep -nE "fetch\(|XMLHttpRequest|WebSocket|EventSource|sendBeacon|import\(['\"]https?:" web/js/parse-fit.worker.js web/js/fit-features.js web/vendor/fitsdk/` returns nothing (`-r` for the directory).
- [ ] AC4: `sw.js` `SHELL` lists `parse-fit.worker.js`, `fit-features.js` and every vendored SDK file, and the cache version is bumped from its E01S03 value. Checked by: `node --test tests/shell-fit.test.js` reads `sw.js` and asserts each file in `web/vendor/fitsdk/*.js` plus the two modules is in `SHELL` and exists on disk, and that the cache version is higher than the E01 value recorded in that test file.
- [ ] AC5 (compliance, DEC-4/FE-1): No Garmin credentials or Garmin Connect calls anywhere, and no unsafe DOM. Checked by: `grep -rniE "password|connect\.garmin|garmin.*(login|sign ?in)" web/` and `grep -rnE "innerHTML|outerHTML|insertAdjacentHTML|document\.write" web/` both return nothing.
- [ ] AC6: manual (Ved): on the installed PWA on his iPhone, in airplane mode, import a `.fit` file from his own Garmin export (kept local, never committed) and see load, fitness and fatigue, with readiness showing "not enough data". On desktop, the Network tab shows zero requests during the import.

> All acceptance criteria must be verifiable. Vague criteria are invalid.
