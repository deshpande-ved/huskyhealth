# Story: Store features only and Forget everything

## User Story

**As an** athlete,
**I want** the app to keep only daily summaries on my phone and to forget them with one tap,
**so that** I don't have to re-import every time, and I stay in control of what's kept.

---

## Context

Plan 10.4 `db.js`: IndexedDB keeps the features JSON (the 6.5 contract) and nothing else from the import: no raw export, no dates, no device names. A visible line says "Stored on this phone: 60 days of summaries". **Forget everything** deletes the database. iOS may clear website data, so storage is a cache: re-importing restores it. The epic's acceptance says "features only", which is stricter than the memory note "features JSON and results"; results are recomputed from features on load.

---

## Acceptance Criteria

- [ ] AC1 (compliance, PRIV-2): `saveFeatures()` stores only the 6.5 keys (`v`, `source`, `window_days`, `max_hr`, `days[]`, `workouts[]` and their listed fields) and drops anything else (e.g. a `date`, `device`, `name` or raw-text field). Checked by `node --test tests/db.test.js` on the allowlist step.
- [ ] AC2: On start, stored features are loaded and the main screen renders from them with no import; with none stored, the screen shows `NO DATA`. Checked by `node --test tests/db.test.js` (IndexedDB stubbed with a store that holds the fixture); manual (Ved): desktop browser, then the installed PWA.
- [ ] AC3: The screen shows "Stored on this phone: N days of summaries" with N from the stored features, or nothing stored. Checked by `node --test tests/db.test.js` on the line's text function.
- [ ] AC4: The **Forget everything** button sits inside `<section id="settings">` in `web/index.html`. It asks for confirmation, then deletes the whole IndexedDB database, clears the in-memory state and returns the screen to `NO DATA`. Checked by `node --test tests/db.test.js` (reads `index.html` for the section; `indexedDB.deleteDatabase` stubbed and called once after confirm); manual (Ved): on iPhone via Web Inspector.
- [ ] AC5 (compliance, PRIV-1 / PRIV-2): only `web/js/db.js` opens IndexedDB, and no health data goes to `localStorage`, `sessionStorage` or cookies. Checked by `grep -rnE "indexedDB|localStorage|sessionStorage|document\.cookie" web/js/` showing `indexedDB` in `db.js` only; `db.js` passes the PRIV-1 network grep.
- [ ] AC6 (R-1): `web/js/db.js` is added to SHELL in `web/sw.js` and `CACHE` is bumped, so the stored-data screen works offline. Checked by `node --test tests/web-sw.test.js` and `grep -n "/js/db.js" web/sw.js`.

> All acceptance criteria must be verifiable. Vague criteria are invalid.
