# Story: Live brief smoke test and numbers-only egress proof

## User Story

**As** Ved, showing judges the privacy claim,
**I want** one script that asks the running stack for a real brief, and mitmweb to show exactly what went to Claude,
**so that** anyone can see that only rounded numbers leave the relay.

---

## Context

With the stack up (E05S04) and the brief route in place (E05S03), a real Claude call goes relay → `egress:8080` (mitmweb) → Anthropic. This story adds a smoke script that drives it through the gateway with the synthetic sample, and checks that the relay and gateway logs stay clean. Reading mitmweb is a human step.

---

## Acceptance Criteria

- [ ] AC1: Given the stack is up with a real key in the local `.env`, when `scripts/brief-smoke.sh http://127.0.0.1:8090` runs, then it prints `token=200 brief=200 text_chars=<n> speak_token=yes` using `tests/fixtures/briefin-sample.json`, and a second POST with the same brief token prints `replay=410`.
- [ ] AC2 [error-handling]: Given `.env` is missing or `ANTHROPIC_API_KEY` is empty, then the script exits non-zero with `ANTHROPIC_API_KEY not set in .env` and never prints any part of `.env`; it never prints request headers or the key (`grep -n "ANTHROPIC_API_KEY" scripts/brief-smoke.sh` shows only the presence test, with no `echo`/`cat` of its value).
- [ ] AC3 [compliance]: After the smoke run, `docker compose logs relay gateway` contains no field name from the sample body (`zone_pct7`, `hrv_z`, `sport_mix`) and none of the returned brief text; the script checks this and prints `logs=clean`.
- [ ] AC4 [compliance]: The egress container has no volumes (`docker inspect` mount count 0), so captured flows live only in its memory. Checked by the script.
- [ ] AC5 [compliance]: manual (Ved): in mitmweb at `http://127.0.0.1:8091`, the one flow to `api.anthropic.com` shows a Request body whose user content is compact JSON of numbers plus the fixed words (call, flags, sport names) and nothing else. Show only the Request body tab, never headers (SAFE-5).
