# Story: Turn workouts into feature rows (sport, zones, effort, source, day)

## User Story

**As an** athlete,
**I want** each of my workouts reduced to a small row (sport, minutes, calories, zone minutes, TRIMP, effort, session-RPE, which day it was and a generic source),
**so that** the engine can score my load without keeping timestamps, device names or my name.

---

## Context

`web/js/features.js` (`toFeatures`, shared later with the Garmin parser) turns the scanner's `{ samples, workouts }` into the 6.5 Features JSON. This story covers the per-workout half: sport mapping, zone minutes and TRIMP (from the engine's `zoneMinutes` / `trimp`, Edwards 1993), effort lookup and session-RPE (engine `srpe`, Foster et al. 2001), relative day, normalized source label, and dedupe of overlapping workouts from other apps, preferring the Watch. Per-day rows and the end-to-end fixture run are E03S04.

---

## Acceptance Criteria

- [ ] AC1: Sport comes from the activity type: `HKWorkoutActivityTypeSquash` → `squash`, `HKWorkoutActivityTypeRunning` → `running`, anything else → `other`. Check: `node --test tests/features.test.js`.
- [ ] AC2: Each workout's `zone_min` and `trimp` come from the engine's `zoneMinutes` and `trimp` (imported from `web/js/engine.js`, not re-implemented), using the window's `max_hr`; a hand-worked example matches. `hr_sample_ok` is `true` when the window holds at least `floor(duration_s / 15)` HR samples (one per 15 s, where `duration_s` = end − start; the input to E02S04's density gate), else `false`. Check: `node --test tests/features.test.js` + `grep -n "from \"./engine.js\"" web/js/features.js`.
- [ ] AC3: `effort` is the user's WorkoutEffortScore inside the workout window, else Apple's EstimatedWorkoutEffortScore, else `null`; `srpe` = effort × minutes via the engine's `srpe`, `null` without effort. Check: three named cases in `tests/features.test.js`.
- [ ] AC4 (compliance, PRIV-2): each workout row has `day` as an integer offset (0 = the local day of `now`, −1 = yesterday) and no absolute timestamp or date; `source` is normalized by this rule: `device` attribute contains "Watch" and "Apple" → "Apple Watch"; else `sourceName` matches `/garmin/i` or `/^connect$/i` → "Garmin"; else "Other app". The raw `sourceName` is never kept (e.g. a fictional `device` of "Test Apple Watch" becomes "Apple Watch"). Check: `node --test tests/features.test.js`.
- [ ] AC5: Two overlapping workouts from different sources (e.g. Watch and a third-party app) become one row, the Watch's. When neither overlapping workout is from the Watch, keep the one with more HR samples, then the earlier start. Non-overlapping workouts are all kept. Check: `node --test tests/features.test.js` (one named test for the no-Watch tie-break).
- [ ] AC6 (error-handling): a workout with no HR samples in its window gets `zone_min: [0,0,0,0,0]`, `trimp: 0`, `hr_sample_ok: false`; missing kcal stays `null`; no exception. `web/js/features.js` has no network calls (PRIV-1 grep: `grep -nE "fetch\(|XMLHttpRequest|WebSocket|EventSource|sendBeacon|importScripts|import\(['\"]https?:|from ['\"]https?:" web/js/features.js` returns nothing) and no DOM access; `web/sw.js` SHELL lists `/js/features.js` with the cache version bumped (R-1; check: `grep -n "features.js" web/sw.js`). Check: `node --test tests/features.test.js` + the grep.

> All acceptance criteria must be verifiable. Vague criteria are invalid.

## Notes

- Decided (round 1): a workout whose source is neither a Watch nor Garmin is labelled "Other app". The raw `sourceName` is never kept.
- STOP condition (H, plan 6.1 spike): effort scores are assumed to appear in the export as Records time-tied to the workout window. E03S05 verifies this on the real export; don't invent a different linkage here.
- Day offsets use the device's local calendar day. Tests pass under both `TZ=UTC` and `TZ=America/New_York` (fixture times chosen away from midnight).
