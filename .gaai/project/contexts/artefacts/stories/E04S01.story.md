# Story: ASCII drawing primitives and call banner font

## User Story

**As an** athlete using HuskyHealth on my phone,
**I want** my training data drawn as clean ASCII figures,
**so that** I can read my load, HRV band and today's call at a glance, with no chart library.

---

## Context

DEC-20 and FE-3 make ASCII the design language. Every figure in the app is built from a small set of pure drawing functions in `web/js/ascii.js`: the 70-step brightness ramp, the HRV band gauge, bars, the 60-day calendar grid, the two-series plot, a painter that fills a `<pre>` without `innerHTML`, and a 5-row block-letter banner for the call (`HARD` / `EASY` / `NO DATA`). The memory file holds a code sketch for all but the banner. These functions take numbers and return text or cell rows, so they are tested in Node with no browser.

---

## Acceptance Criteria

- [ ] AC1: `RAMP` has exactly 70 characters, runs dense → light, and `rampChar(1)` returns its first character and `rampChar(0)` its last; values outside 0–1 are clamped. Checked by `node --test tests/ascii.test.js`.
- [ ] AC2: `gauge(0)` returns `[...........|====o====|...........]`; `gauge(-3)` puts `o` at the left edge (clamped to −2 SD) and `gauge(3)` at the right edge. `bar(31)` returns 6 `#` then 14 `.`; `bar(0)` and `bar(100)` return 20 `.` and 20 `#`. Checked by `node --test tests/ascii.test.js`.
- [ ] AC3: `calendar()` on 60 daily loads returns 7 rows holding all 60 days; a 0 load gives the lightest ramp character; each cell's class is `z0`…`z5` from the dominant zone. `plot(a, b, 44, 10)` returns 10 lines of exactly 44 characters with `+` for the first series and `o` for the second. Checked by `node --test tests/ascii.test.js`.
- [ ] AC4: `banner(word)` draws `HARD`, `EASY` and `NO DATA` as exactly 5 rows each, no row wider than 44 columns, using a hand-drawn font covering only A D E H N O R S T Y; an unknown letter throws. Checked by `node --test tests/ascii.test.js`.
- [ ] AC5 (compliance, FE-1 / PRIV-1): `ascii.js` touches the DOM only inside `paint()`, which uses `createElement`, `textContent` and `replaceChildren`. `grep -nE "innerHTML|outerHTML|insertAdjacentHTML|document\.write|fetch\(|XMLHttpRequest|WebSocket" web/js/ascii.js` returns nothing, and the module imports in Node without a `document` (the test file imports it).
- [ ] AC6 (R-1): `web/sw.js` SHELL gains `/js/ascii.js` and `CACHE` is bumped, so the installed app gets the module offline. Checked by `node --test tests/web-sw.test.js` and `grep -n "/js/ascii.js" web/sw.js`.

> All acceptance criteria must be verifiable. Vague criteria are invalid.

## Notes

- Start from the sketch in the memory file. The sketch's `RAMP` string was counted at 70 characters during Discovery; if the string you paste is not 70, stop and report rather than padding it.
- In the sketch, a `z` just outside the band (e.g. 0.6) overwrites the right `|` with `o`. That is fine; keep it.
- Font: 5 rows high, letters about 5 columns wide plus a 1-column gap, so `NO DATA` fits in 44 columns.
- Tests use `node:test` and `node:assert` only; no new dependencies.
