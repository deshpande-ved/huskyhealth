# Story: Show recent studies on References cards

## User Story

**As a** judge or curious player,
**I want** each References card to offer three recent cited studies with a one-line summary on tap,
**so that** I can check the method against current science in a tap.

---

## Context

Feature F19 "Evidence agent", part 2: tap-to-load, Claude summaries and the References UI. **Cut together with E10S06**; the two ship or are cut as one unit, independent of F16, F17 and F18 (DEC-18). Shipping F19 adds a Surge track listing (DEC-23).

- Nothing loads when a References card opens. A "Show recent studies" button starts the request. A one-line notice beside it names Anthropic Claude and Tavily, for example: "Tapping sends a fixed search to Tavily; Anthropic Claude writes the summaries."
- The tap calls `/v1/evidence/<method_id>` once; the request carries only the method id.
- Search results go through Presidio before Claude sees them (PRIV-8), and Claude's lines are checked again. Claude writes one line per source from the title and snippet only.
- No user data reaches Claude or the search provider here. The notice and the tap are the disclosure (PRIV-5).
- The section is labelled as found by a search agent and summarised by Claude. References must still work offline; this section is the only part that needs the network.
- **STOP:** if fewer than 3 results survive Presidio for the readiness id, stop and report. Do not weaken PRIV-8, and do not borrow the redactor from E10S02; PRIV-8 uses `pii_types()` only.

---

## Acceptance Criteria

- [ ] AC1 (compliance): `pii_types()` runs on each result's title and snippet before Claude; a result with any finding is dropped (count only to `AUDIT`); Claude's lines are checked too and a line with a finding is replaced by the source title. Checked by pytest with a mocked search result holding a person's name. The STOP in Context applies if fewer than 3 results survive for the readiness id.
- [ ] AC2 (compliance): the summary prompt asks for one line (≤ 25 words) per source in training language, no medical advice; a line matching the CLAIM-1 pattern is replaced by the source title; summaries are cached with the results per method. Checked by pytest with a mocked Claude client.
- [ ] AC3 (compliance): opening a References card makes no request: `node --test` with a stubbed `fetch` records zero calls on open. The card shows the "Show recent studies" button and the notice, and the notice text names both Anthropic Claude and Tavily. Tapping the button fetches the id once and shows up to 3 items.
- [ ] AC4: items are rendered with `createElement` / `textContent` (title as a link, one-line summary, "found by a search agent, summarised by Claude"); links are `https:` only, with `rel="noopener noreferrer"`, so a `javascript:` URL is not rendered. `web/js/evidence.js` is added to `SHELL` in `web/sw.js` with a `CACHE` bump, so the card renders offline. `web/_headers` is unchanged, so CSP `connect-src` stays as it is. Checked by `node --test`, the FE-1 greps in `frontend.rules.md`, a grep of `web/sw.js`, and `git diff web/_headers` (empty).
- [ ] AC5 (error-handling): offline, 404 or 503 shows "Recent studies need a connection" or "Recent studies unavailable" beside the button; the rest of the card renders unchanged; nothing retries automatically. Checked by `node --test` with a stubbed `fetch` per case.
- [ ] AC6: manual (Ved): on the installed PWA, opening the readiness card makes no request in mitmweb; tapping "Show recent studies" shows 3 cited sources; in airplane mode the card still renders and the button shows the offline message.
