# Story: Manifest and placeholder icons

## User Story

**As an** athlete on an iPhone,
**I want** HuskyHealth to have a name and icon when I add it to my Home Screen,
**so that** it opens like an app, full screen.

---

## Context

The web app manifest and icons make the page installable (DEC-1). The icons are placeholders until the ASCII husky mark exists; they must be original work, never a third-party trademark (FE-5).

---

## Acceptance Criteria

- [ ] AC1: `web/manifest.webmanifest` parses as JSON and deep-equals the manifest in `infra-pwa.md` (name, short_name, start_url, scope, display `standalone`, the two icon entries with the 512 one `"purpose": "any maskable"`, `background_color` and `theme_color` `#191724`). Checked by `node --test tests/web-manifest.test.js`.
- [ ] AC2: `web/icons/icon-192.png` is a valid PNG of 192×192 and `web/icons/icon-512.png` of 512×512, read from the PNG IHDR header. Checked by `node --test`.
- [ ] AC3: `web/icons/apple-touch-icon.png` is a valid 180×180 PNG with no transparency (opaque background). Checked by `node --test` (IHDR size, color type without alpha).
- [ ] AC4: (compliance, FE-5) the icons are original placeholders (for example a solid background with a simple geometric shape or letters), with no third-party logo or trademark, never Northeastern's Paws. The generator script is committed so anyone can see how they were made. Checked by `grep -nE "readFile|fetch|https?://" scripts/make-icons.mjs` returning nothing (the script reads and fetches nothing). manual (Ved): viewing the three PNGs shows original placeholder art with no third-party mark.
- [ ] AC5: `scripts/make-icons.mjs` regenerates all three PNGs with Node built-ins only (no npm install, no network). Checked by running `node scripts/make-icons.mjs` and then the AC2/AC3 tests.

> All acceptance criteria must be verifiable. Vague criteria are invalid.
