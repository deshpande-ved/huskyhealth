# Story: Brief route that asks Claude through egress

## User Story

**As an** athlete,
**I want** to send my rounded numbers once and get back two or three sentences explaining today's call,
**so that** I understand why to go hard or keep it easy, without the AI ever changing the call.

---

## Context

`POST /v1/brief` burns a brief token, validates `BriefIn`, rounds the values (`bucketize`), sends them to Claude through the egress proxy, and returns `{text, speak_token}` with the speak token bound to a hash of `text`. The route sketch, `ai.py`, the system prompt and the rounding table are in the memory sources. Rules decide, AI explains (CLAIM-3, DEC-6/7).

---

## Acceptance Criteria

- [ ] AC1: Given a valid brief token and the synthetic `tests/fixtures/briefin-sample.json`, with the Anthropic client mocked to return fixed text, when `POST /v1/brief` is called, then it returns 200 with exactly the keys `text` and `speak_token`, and `burn(speak_token, "speak", bound=digest(text))` is `True` while a different text gives `False`. Checked by `pytest tests/relay/test_brief.py`.
- [ ] AC2 [error-handling]: Given a missing, unknown, expired, wrong-kind or already-used token, then the route returns 410 before reading the body; given a body that is not JSON or fails `BriefIn`, then it returns 422 `{"error": "rejected", "schema_ok": false, "pii": []}` (or `{"error": "not JSON"}`) and never echoes the input. Checked by pytest (replay of the same token → 410).
- [ ] AC3 [compliance]: Given the mocked client, when a brief is made, then the user message sent to Claude is compact JSON of `bucketize(s)` whose every string value is from the fixed set (`hard`, `easy`, `not_enough_data`, `monotony`, `load_spike`, the `Sport` names as keys) and every number is rounded to the step in the rounding table. Checked by pytest.
- [ ] AC4 [compliance]: The Anthropic client is built with `base_url=os.environ["ANTHROPIC_BASE_URL"]` (no hard-coded Anthropic host in `relay/`), model and `max_tokens` match the memory source, and the key is read only from the `ANTHROPIC_API_KEY` env by the SDK. Checked by pytest (env monkeypatched), `grep -rn "api.anthropic.com" relay/` returning nothing, and `grep -rnE "sk-ant-[A-Za-z0-9_-]{20,}" relay nginx egress scripts docker-compose.yml .env.example` returning nothing.
- [ ] AC5 [compliance]: CLAIM-3: the response never contains a `call` field, and the system prompt keeps the exact sentence "Explain the call, never change it." plus the load-alert wording rule. CLAIM-1: the only `relay/` hits of the CLAIM-1 grep in `claims.rules.md` are the two negated phrases inside `SYSTEM` ("injury risk", "medical advice or diagnoses"), which are not user-facing. Checked by pytest and that grep.
- [ ] AC6 [error-handling]: Given `app.pii_types` monkeypatched (the name `relay/app.py` imports, not `pii.pii_types`) to return a finding for incoming strings, for the prompt, or for Claude's text, then the route returns 422 and no text or speak token leaves; with the shipped no-op stub, findings are `[]`. Checked by pytest (proves E08's hook points).
