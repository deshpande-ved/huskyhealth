# Story: Service worker with the shell SHELL list

## User Story

**As an** athlete with the app installed,
**I want** it to open with no network,
**so that** I can use it anywhere and know my data isn't going anywhere.

---

## Context

The service worker caches the app shell so the installed PWA runs offline (DEC-1, DEC-2). Relay calls under `/v1/` are never cached. The code sketch in `infra-pwa.md` is the spec.

---

## Acceptance Criteria

- [ ] AC1: `web/sw.js` declares `CACHE = "huskyhealth-v1"` and a `SHELL` array of exactly these seven entries: `/` (maps to `web/index.html`), `/index.html`, `/css/style.css`, `/js/app.js`, `/manifest.webmanifest`, `/icons/icon-192.png`, `/icons/icon-512.png`. Each is also in the 10.4 list in `infra-pwa.md`, and each maps to a file under `web/`, so `addAll` cannot fail on a missing file. Checked by `node --test tests/web-sw.test.js`, which loads `sw.js` in a `node:vm` context with stub `self`, `caches` and `fetch`, and checks each entry against the disk. The test asserts these seven are a subset of SHELL and that CACHE matches `^huskyhealth-v\d+$` (not exact values), so later stories can grow SHELL and bump CACHE by editing only their own expected-entries list in this test.
- [ ] AC2: On `install`, the worker opens `CACHE` and calls `addAll(SHELL)`; on `activate`, it deletes every cache whose name is not `CACHE`. Checked by the same test with recorded stub calls.
- [ ] AC3: (compliance, PRIV-2/PRIV-9) a `fetch` event for any path starting with `/v1/` is not answered by the worker (no `respondWith`), so relay traffic is never cached. Checked by the same test.
- [ ] AC4: Any other `fetch` event is answered cache-first, falling back to the network. Checked by the same test (hit returns the cached response; miss calls `fetch`).
- [ ] AC5: `web/js/app.js` registers `/sw.js` when `navigator.serviceWorker` exists and does nothing when it doesn't; no inline script is added (FE-1). Checked by `grep -nE "serviceWorker\.register\(['\"]/sw\.js['\"]" web/js/app.js` plus the FE-1 greps from E01S01 AC2.

> All acceptance criteria must be verifiable. Vague criteria are invalid.

## Out of Scope

- SHELL entries beyond the seven listed in AC1. Later epics add their own, under the rule in Notes.
- Adding `/vendor/fitsdk/` files to SHELL (the Garmin epic does that when it vendors them, under the same rule).
- Offline checks on a phone (E01S05).

## Notes

- **SHELL growth rule (R-1, Ved 2026-11-07):** `cache.addAll` is all-or-nothing, so a SHELL entry must exist in the same change that adds it. Any later story that adds a file the app needs offline, or changes a file already in SHELL, adds it to SHELL and bumps `CACHE` in `web/sw.js` in one of its own ACs, checked by the test or a grep, so installed copies update. Do not swallow the install error.
- `apple-touch-icon.png` and `version.txt` are not in the 10.4 SHELL list; keep them out.
- Keep the `CACHE` name a single constant on one line so later deploys can bump it.
