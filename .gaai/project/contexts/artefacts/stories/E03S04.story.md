# Story: Build the full Features JSON and prove it on the synthetic fixture

## User Story

**As an** athlete,
**I want** my import to end in one small Features JSON holding 60 days of daily numbers and workout rows,
**so that** the engine and screens have everything they need and nothing identifying is kept.

---

## Context

Completes `toFeatures()` with the top-level fields and per-day rows from the 6.5 contract, and wires it into the worker's final message. Then proves the epic's main acceptance item: the hand-written `tests/fixtures/synthetic-export.xml` parses, as `.xml` and as an in-memory `.zip`, to the expected features.

---

## Acceptance Criteria

- [ ] AC1: `toFeatures` returns `{ v: 1, source: "apple_health", window_days: 60, max_hr, days, workouts }`; `max_hr` is the highest HR sample in the window, rounded. Check: `node --test tests/features.test.js`.
- [ ] AC2: `days` has one row per day in the window (oldest → today, `day` from −(window_days−1) to 0) with `trimp` (sum, 0 if no workouts), `srpe` (sum, `null` if no rated effort), `rhr` (mean of that day's resting HR, `null` if none), `ln_hrv` (mean of ln(SDNN) of that day's readings, `null` if none) and `vo2` (that day's reading, else `null`); hand-worked values match. Check: `node --test tests/features.test.js`.
- [ ] AC3: The worker's final message is `{ done: true, features }`. Importing the fixture as `.xml` and as an in-memory `.zip` (fixed injected `now`) both deep-equal the hand-checked `tests/fixtures/synthetic-features.expected.json`. The expected workouts carry `hr_sample_ok` (`false` for the sparse workout, `true` for the others); a named assertion checks every workout row has a boolean `hr_sample_ok`. Check: `node --test tests/parse-apple-e2e.test.js`, passing under `TZ=UTC` and `TZ=America/New_York`.
- [ ] AC4 (compliance, PRIV-2 / DEC-13): a deep scan of the fixture's features finds no epoch-millisecond numbers, no date or time strings, no raw `sourceName` (the fixture's fictional device names), no route/ECG/clinical content, and no keys outside the 6.5 contract plus the per-workout `hr_sample_ok` boolean (R-4c). Check: a named test in `tests/parse-apple-e2e.test.js`.
- [ ] AC5 (error-handling): an export with no kept records (e.g. `<HealthData/>` only, built in the test) returns valid features with 60 empty day rows (`rhr`, `ln_hrv`, `vo2`, `srpe` `null`; `trimp` 0), `workouts: []` and `max_hr: null`, not an exception. Check: `node --test tests/parse-apple-e2e.test.js`.
- [ ] AC6 (compliance, PRIV-1): `grep -nE "fetch\(|XMLHttpRequest|WebSocket|EventSource|sendBeacon|importScripts|import\(['\"]https?:|from ['\"]https?:" web/js/parse-apple.worker.js web/js/features.js` returns nothing; `web/sw.js` CACHE bumped; `node --test tests/web-sw.test.js` green.

> All acceptance criteria must be verifiable. Vague criteria are invalid.
