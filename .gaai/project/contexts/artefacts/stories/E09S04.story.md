# Story: GoldenCheetah cross-check steps and comparison scripts

## User Story

**As** Ved, the builder,
**I want** written steps and two small local scripts to compare our fitness/fatigue with GoldenCheetah's CTL/ATL on the same `.fit` files,
**so that** I can show judges and users that the engine is implemented and fed correctly, with a real correlation number.

---

## Context

Plan 7.4 layer 2 (F15, DEC-22): import the same `.FIT` files into GoldenCheetah (GPL v2), set HR zones at 50/60/70/80/90 % of the same max HR, build the PMC from **TRIMP Zonal Points**, and compare CTL/ATL with our fitness/fatigue day by day. Target: the curves overlap after the seeding windows; report the correlation on References.

T-1: the GoldenCheetah run is "manual (Ved)". Delivery writes the steps and the scripts and tests them on synthetic series. Delivery does not run GoldenCheetah and does not claim a correlation.

No GoldenCheetah code enters HuskyHealth (GPL v2). Ved's real `.fit` files and every file derived from them stay local, under the gitignored `tests/fixtures/real_*` path (SAFE-1).

---

## Acceptance Criteria

- [ ] AC1: `scripts/gc-crosscheck/our-series.mjs <dir-of-fit-files> --end YYYY-MM-DD` takes `--end YYYY-MM-DD` as `now` and `--days N` (default: the span from the earliest file's date to `--end`), runs `fitToFeatures(buffers, { days, now })` (E09S02) and the engine's `fitnessFatigue()` (E02S02) on the local files, and writes `date,fitness,fatigue` rows plus the `max_hr` it used. Checked by: `node --test tests/gc-crosscheck.test.js` runs it on synthetic FIT bytes from `tests/fixtures/fit-synthetic.js`.
- [ ] AC2 (compliance, SAFE-1): Both scripts write output only under `tests/fixtures/real_gc/` and refuse any output path that `git check-ignore` does not ignore. No network calls. Checked by: a test of the refusal, and the PRIV-1 grep on `scripts/gc-crosscheck/` returns nothing.
- [ ] AC3: `scripts/gc-crosscheck/compare.mjs <ours.csv> <goldencheetah.csv>` aligns rows by date, drops the first 42 days (seeding window), and prints the Pearson r for fitness vs. CTL and fatigue vs. ATL plus the number of days compared. Column names for the GoldenCheetah file are flags with defaults. Checked by: `node --test` with hand-worked series (identical series → r = 1.00; a known small series → its hand-computed r).
- [ ] AC4 (error-handling): `compare.mjs` exits non-zero with a one-line message (no data echoed) when a column is missing, the files share fewer than 14 days after seeding, or a series is constant. Checked by: `node --test`.
- [ ] AC5: `docs/goldencheetah-crosscheck.md` lists the steps for Ved: install GoldenCheetah and record its version (`gc_version` for `validation.js`); set the athlete's max HR to the `max_hr` printed by `our-series.mjs`; set HR zones at 50/60/70/80/90 % and set the TRIMP zone weights to 1/2/3/4/5, or record that GoldenCheetah does not expose them (an unverified assumption); import the same `.fit` files; use TRIMP Zonal Points as the PMC metric; export daily CTL/ATL as CSV into `tests/fixtures/real_gc/`; run both scripts; paste the r values into `web/js/validation.js` (E09S05). Checked by: `grep -c` finds each of "max HR", "TRIMP Zonal Points", "50/60/70/80/90", "1/2/3/4/5", "gc_version", "real_gc", "validation.js" in the doc.
- [ ] AC6: manual (Ved): runs the steps on his own `.fit` files and gets two r values and a day count. Delivery provides the steps and does not claim this passed.

> All acceptance criteria must be verifiable. Vague criteria are invalid.

## Notes

- H-2 (unverified): how GoldenCheetah exports daily CTL/ATL (chart data export or a metrics trend export). The doc must say which menu Ved used once he has checked; column names are flags so the script adapts. If GoldenCheetah cannot export daily CTL/ATL at all, Ved reports it and Discovery decides; do not scrape or reimplement GoldenCheetah.
- Our features use day offsets, not dates; `our-series.mjs` turns offsets back into dates from `--end` only for this local, gitignored output.
- Pearson r is unitless, so different decay constants or scaling between the tools do not break the comparison.
