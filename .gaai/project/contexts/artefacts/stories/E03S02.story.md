# Story: Import a .zip or .xml file in the worker, with progress

## User Story

**As an** athlete,
**I want** to hand over either the `export.zip` my iPhone makes or an unzipped `export.xml`, and see that it's working,
**so that** a multi-gigabyte import doesn't look frozen and nothing besides `export.xml` is touched.

---

## Context

The export is big (published example: 79 MB zip → 2.45 GB). The worker streams the file: `.xml` straight through the scanner; `.zip` through `fflate`'s streaming `Unzip`, decompressing only the `export.xml` entry and skipping routes, ECGs, `export_cda.xml` and everything else. It posts progress while scanning and a final message when done. `fflate` (MIT) is vendored at `web/vendor/fflate.esm.js`; this story adds that path to `SHELL` in `web/sw.js` (R-1).

Until E03S04 wires in `features.js`, the done message may carry the scanner's counts; E03S04 replaces that with the Features JSON.

---

## Acceptance Criteria

- [ ] AC1: Given `tests/fixtures/synthetic-export.xml` as a `.xml` File, the worker's import function streams it (via `file.stream()`, never reading it whole) and returns the same scan result as E03S01. Check: `node --test tests/parse-apple-file.test.js`.
- [ ] AC2: Given a zip built **in memory inside the test** (with `fflate`; no `.zip` is ever written to the repo, SAFE-1) holding `apple_health_export/export.xml` (the fixture), `export_cda.xml`, `workout-routes/route_1.gpx` and `electrocardiograms/ecg_1.csv`, the import gives the same result as the `.xml` path. Check: `node --test tests/parse-apple-file.test.js`.
- [ ] AC3 (compliance, DEC-13 / PRIV-3): in that zip test, only the `export.xml` entry is started/decompressed; the route, ECG and `export_cda.xml` entries are never started (asserted by a spy or by checking that their contents never reach the scanner). Check: a named test in `tests/parse-apple-file.test.js`.
- [ ] AC4: The worker posts at least one `{ progress: <lines scanned>, bytes: <file bytes read>, total: file.size }` message (for E04S10's progress bar) before its final `{ done: true, … }` message, also for the small fixture (progress interval injectable or a final progress post). Check: `node --test tests/parse-apple-file.test.js`.
- [ ] AC5 (error-handling): a zip with no `export.xml` posts `{ error: "export.xml not found in this zip" }`; a corrupt zip or unreadable file posts an `{ error }` message; neither leaves the worker hanging. Check: named tests in `tests/parse-apple-file.test.js`.
- [ ] AC6 (compliance, PRIV-1): `grep -nE "fetch\(|XMLHttpRequest|WebSocket|EventSource|sendBeacon|importScripts|import\(['\"]https?:|from ['\"]https?:" web/js/parse-apple.worker.js` returns nothing; the only import is the local `../vendor/fflate.esm.js` (and `./features.js` later). `web/vendor/fflate.LICENSE` (MIT) is present. `web/sw.js` SHELL lists `/vendor/fflate.esm.js` with the cache version bumped (R-1; check: `grep -n "fflate.esm.js" web/sw.js`).

> All acceptance criteria must be verifiable. Vague criteria are invalid.

## Notes
