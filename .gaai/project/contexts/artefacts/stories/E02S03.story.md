# Story: The readiness band

## User Story

**As an** athlete,
**I want** a HARD or EASY call for today from my HRV trend against my own baseline, or a plain "not enough data",
**so that** I know whether a hard session makes sense today, decided by a published rule and not by guesswork.

---

## Context

Third engine story. It adds the readiness rows of the 7.1 table to `web/js/engine.js`, following the 7.2 `readiness` sketch:
- readiness call: 7-day rolling mean of daily ln(HRV) vs. baseline mean ± 0.5 SD; inside → `hard`, outside either way → `easy` (Plews et al. 2013–14, **adapted**: the Watch gives SDNN at random times, the studies used morning rMSSD);
- data check: ≥ 3 days with HRV in the last 7 (Plews et al. 2014, published);
- baseline length: ≥ 14 days with HRV before the last 7 (ours, labeled as ours).

DEC-7: the call has exactly two states plus no data. No middle state.

---

## Acceptance Criteria

- [ ] AC1: Hand-worked HARD: baseline of 14 days alternating ln(HRV) 4.0 / 4.2 (mean 4.1, sample SD ≈ 0.1038) and last 7 days all 4.1 → `call: "hard"`, `z` with |z| < 1e-9, `n7` 7, `nBase` 14. Checked by `node --test "tests/**/*.test.{js,mjs}"`.
- [ ] AC2: Hand-worked EASY both ways: same baseline, last 7 days all 4.0 → `easy` with `z` ≈ −0.964; last 7 days all 4.2 → `easy` with `z` ≈ +0.964. Checked by `node --test "tests/**/*.test.{js,mjs}"`.
- [ ] AC3: Data check: last 7 days with exactly 3 non-null readings (others `null`) gives a call; exactly 2 gives `call: "not_enough_data"` with `n7: 2`. Checked by `node --test "tests/**/*.test.{js,mjs}"`.
- [ ] AC4: Baseline length: 13 non-null baseline days → `not_enough_data` with `nBase: 13`; 14 → a call. Only days before the last 7 count toward the baseline. Checked by `node --test "tests/**/*.test.{js,mjs}"`.
- [ ] AC5 (compliance, FE-2 / DEC-6 / DEC-7): the result carries `source` for `readiness` (status `adapted`), and the `not_enough_data` result names which check failed in `failed` with the source of `data-check` (status `published`) or `baseline` (status `ours`); when both checks fail, `failed: ["data-check","baseline"]`. The call is only ever `hard`, `easy` or `not_enough_data`. Checked by `node --test "tests/**/*.test.{js,mjs}"`.
- [ ] AC6 (compliance, PRIV-1): `tests/engine/purity.test.mjs` still passes; `CACHE` in `web/sw.js` is bumped, checked by `node --test tests/web-sw.test.js`; and the full scoped run `node --test "tests/**/*.test.{js,mjs}"` is green.

## Notes

- Input: `dailySeries(features, "ln_hrv", null)` (oldest → today; `null` where no reading). Features already hold the mean ln(SDNN) per day.
- Baseline SD is the sample SD (n − 1), as in the 7.2 sketch. If SD is 0, `z` is 0 and the call follows `|roll − mu| ≤ 0`.
- Wording is training language only (CLAIM-1): "hard" / "easy" are training calls, not health statements.
