# Story: Safe Harbor and threat-model text for a slide

## User Story

**As** a judge or prospective team,
**I want** to see HuskyHealth's data handling checked against the 18 HIPAA Safe Harbor identifiers and a who-can-see-what threat model,
**so that** I can compare the privacy claims to a recognized standard.

---

## Context

HIPAA doesn't legally cover a consumer app; Safe Harbor is the benchmark (plan 9.4). The evidence memory holds the checklist (rows A–R, grouped as 10 rows: A, B, C, D–L, M, N, O, P, Q, R) and the threat model (plan 9.5, 12 rows). This story turns them into public, slide-ready text in the repo. The threat-model table is kept in full; it is not optional.

---

## Acceptance Criteria

- [ ] AC1: `docs/safe-harbor.md` contains the Safe Harbor table covering all 18 identifiers (rows A–R, with D–L grouped as in memory) and one line stating that HIPAA doesn't legally cover a consumer app and Safe Harbor is used as the benchmark. Check: grep for each row letter A, B, C, D–L, M, N, O, P, Q, R.
- [ ] AC2: the table is slide-ready: the Safe Harbor table comes first in the file, before the threat-model table; one row per identifier group (10 rows), each HuskyHealth cell ≤ 25 words. Check: the first `|` table in the file is the Safe Harbor table. Shorten memory wording where needed; the P row is the longest. Check: `awk -F'|' '/^\|/ {seen=1; if ($4 !~ /HuskyHealth|---/) {n=split($4,w," "); if (n>25) print NR": "n}} seen && /^$/ {exit}' docs/safe-harbor.md` prints nothing; manual (Ved): it fits on one slide.
- [ ] AC3: the same file contains the threat-model table (who / what they could see / mitigation and proof) with all 12 rows from the memory, including the convenience-mode and voice check-in rows, each marked opt-in and OFF by default. Check: grep for "Venue Wi-Fi", "Tailscale Funnel", "Anthropic", "Gradium", "convenience mode", "voice check-ins"; `grep -c "OFF by default" docs/safe-harbor.md` prints at least 2.
- [ ] AC4 (compliance): CLAIM-2 and CLAIM-1 wording: the file says "de-identified", never "anonymous"/"anonymized", never "injury risk", and never claims HIPAA compliance or certification. Check: `grep -niE "anonymous|anonymi[sz]|injury risk|hipaa[- ]compliant|certified" docs/safe-harbor.md` returns nothing.
- [ ] AC5 (compliance): public-repo safe (SAFE-2): no homelab hosts beyond the relay origin, no LAN IPs, SSH aliases, private ports or real names. The device-name example uses a made-up name (e.g. "Sam's Apple Watch"), and the threat-model "who" column says "the Pi operator", not a name. Check: `grep -nE "[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+|\bssh\b" docs/safe-harbor.md` returns nothing; `grep -noE "https?://[^ )\"]+" docs/safe-harbor.md` shows at most the relay origin; `grep -niwE "ved|deshpande" docs/safe-harbor.md` returns nothing; manual (Ved): the private runbook's D5 scrub grep, pointed at `docs/safe-harbor.md`, prints `clean`.
