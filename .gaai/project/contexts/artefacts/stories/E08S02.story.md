# Story: Block PII on the brief route and audit counts only

## User Story

**As an** athlete asking for a coaching brief,
**I want** the relay to refuse any request, prompt or reply that contains identifying text,
**so that** nothing identifying reaches Claude or comes back to be read aloud.

---

## Context

PRIV-8 requires Presidio on every outbound path of the brief flow: the incoming JSON (before anything else), the bucketed prompt sent to Claude, and Claude's text before anyone hears it. E05S03 built the route with no-op scan hooks; this story turns the hooks on using `relay/pii.py` from E08S01, following the order in the memory sketch (plan 10.5). The demo's proof beat is the smuggle fixture: a brief with a device name hidden in an extra field is rejected with `schema_ok=false` and `pii=["DEVICE_NAME"]`. `/v1/audit` shows counts only (PRIV-6).

---

## Acceptance Criteria

- [ ] AC1: `tests/fixtures/brief_smuggle.json` (a valid synthetic brief plus one extra string field holding a made-up `<name>'s Apple Watch`) POSTed to `/v1/brief` with a fresh brief token → 422 with body exactly `{"error": "rejected", "schema_ok": false, "pii": ["DEVICE_NAME"]}`. Check: `pytest tests/relay/test_brief_pii.py` (Flask test client).
- [ ] AC2: the incoming JSON is scanned before `BriefIn` validation, so a PII hit is reported even when the schema also fails; a body that is not JSON → 422 `{"error": "not JSON"}`; Claude is never called on any 422 path. Check: pytest with `claude_brief` mocked and asserted not called.
- [ ] AC3: the bucketed prompt is scanned before Claude is called, and Claude's text is scanned before it is returned; if the mocked Claude text contains a device name, the route returns 422 `{"error": "blocked"}` with no `text` and no speak token. Check: pytest with `claude_brief` mocked; `pii_findings` rises by the number of hits on the blocked block (1 here), and a device name injected into the bucketed prompt also gives 422 with Claude never called.
- [ ] AC4: with `tests/fixtures/brief_synthetic.json` and a clean mocked Claude reply, the route returns 200 with `text` and `speak_token` (0 findings). Also, E05's `tests/relay/test_brief.py` still passes with the real scanner. Check: `pytest tests/relay`.
- [ ] AC5 (compliance): `GET /v1/audit` (added here) returns counts only (`briefs`, `blocked`, `pii_findings`); after the smuggle request `pii_findings` rises by 1. No log line or audit field contains request content, matched text, prompt or brief text (PRIV-6). Check: pytest captures logs during the smuggle request and asserts the device name string is absent; `grep -rnE "log(ger)?\.\w+\(.*(body|request\.json|brief|prompt|audio|errors\(\))" relay/` returns nothing.
- [ ] AC6 (compliance): no test makes a network call: Claude is mocked, and `pytest tests/relay` passes with the E08S01 socket guard (`tests/relay/conftest.py`) on. Check: `grep -rn "ANTHROPIC_API_KEY" tests/relay` returns nothing.
