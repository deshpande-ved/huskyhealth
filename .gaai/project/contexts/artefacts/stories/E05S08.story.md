# Story: Brief screen with preview, consent and send

## User Story

**As an** athlete,
**I want** to see exactly what will be sent to Anthropic, agree to it, and only then get my brief,
**so that** nothing leaves my phone without my knowing and choosing it, and my training call stays the engine's.

---

## Context

Under the call banner, **Get coaching brief** opens a preview of the exact `BriefIn` JSON (from E05S07), names the provider ("Anthropic (Claude), through the HuskyHealth relay"), and asks for consent to that provider (PRIV-5). **Send** then mints a brief token and posts the previewed string to the relay origin. The brief text appears under the call; the call banner never changes (CLAIM-3).

---

## Acceptance Criteria

- [ ] AC1 [compliance]: Anthropic consent is OFF on first run and after **Forget everything**; while it is off, no request reaches the relay. Checked by `node --test tests/relay-client.test.js` with a stubbed `fetch` (zero calls) and a test on the default settings.
- [ ] AC2 [compliance]: The preview shows `JSON.stringify(briefIn, null, 2)` as text in a `<pre>` and names the provider as "Anthropic (Claude)", and the request body sent is the identical object (`JSON.parse(previewText)` deep-equals the posted body). If `buildBriefIn` returns `null`, the button says the brief is not available and nothing is sent. Checked by node --test.
- [ ] AC3: **Send** calls `POST {RELAY}/v1/token?kind=brief`, then `POST {RELAY}/v1/brief` with `Authorization: Bearer <token>`, where `RELAY` equals the relay origin in `web/_headers` `connect-src`; the brief is shown with `textContent`; the `speak_token` is kept in memory only, never in IndexedDB. Checked by node --test and `grep` of `_headers`.
- [ ] AC4 [error-handling]: On 410, 422, 429, a network error or a timeout, the screen shows a plain message ("Brief not available right now"), keeps no partial text, and the call banner and its numbers are unchanged before and after any brief response or error (CLAIM-3). Checked by node --test.
- [ ] AC5: FE-1 and offline shell: the FE-1 greps return nothing for the new files, and the E01S01 `https?://` grep still passes; `/js/relay-client.js` is added to `web/sw.js` SHELL, the cache name is bumped again, `/js/brief.js` (from E05S07) is still listed, and `/v1/` stays network-only. Checked by `node --test tests/web-sw.test.js` and grep.
- [ ] AC6: manual (Ved): on the installed PWA (Pages preview) against the Pi relay, preview → consent → Send shows a brief under an unchanged call, and the Claude request in mitmweb deep-equals the previewed JSON without `v` (`JSON.parse(previewText)` minus `v`), with no value changed by the relay's `bucketize`.

## Notes

- Keep network code in `web/js/relay-client.js` (`sendBrief(bodyString, fetchImpl)`) so it is testable in node without a DOM; DOM wiring stays thin in `app.js`.
- Copy: "de-identified", never "anonymous" (CLAIM-2); "load alert", never anything about injury (CLAIM-1).
- Request timeout ~20 s via `AbortController`. No retries that would reuse a token.
- `db.js` is one IndexedDB database from E04S06. E04S06 leaves settings to later epics and says they add their own stores to the same database, so this story adds a `settings` object store there with a version bump. Do not open a second database. STOP only if E04S06's `db.js` has no upgrade path for a new store; then stop and report.
