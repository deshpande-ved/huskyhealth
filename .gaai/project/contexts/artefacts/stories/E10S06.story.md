# Story: Relay finds recent studies with fixed queries

## User Story

**As a** judge or curious player reading a References card,
**I want** recent studies on that method found for me,
**so that** I can see the science is current without anything about me being searched.

---

## Context

Feature F19 "Evidence agent" (2.5–3 h), part 1: search, fixed queries and cache. **Cut together with E10S07**; the two ship or are cut as one unit, independent of F16, F17 and F18 (DEC-18).

- **DEC-23:** if F19 ships, the project also lists the Surge track (Tavily).
- Queries come only from a fixed list per method (e.g. "HRV-guided training rolling average smallest worthwhile change"). No user numbers, dates, sports or text ever go into a query (PRIV-2). The route takes only a method id.
- Results are cached per method on the relay (no user data). Uses hackathon Tavily credits; the key lives in `.env` only (SAFE-1, SAFE-5).
- Take endpoint, auth header and body from Tavily's API reference; never guess.
- **Port:** search egress is a third mitmweb reverse listener on internal port 8083 (`egress:8083`), on the compose network only, never published on the host. 8083 is an allowed port in committed files (R-2); no other port is added.

---

## Acceptance Criteria

- [ ] AC1: `GET /v1/evidence/<method_id>` serves only ids in a fixed table (one entry per References card from engine.md 7.1, each with 1–2 fixed query strings); an unknown id → 404; a request body or query string → 400. Checked by pytest.
- [ ] AC2 (compliance): the outbound search request carries exactly one fixed query string from the table and nothing else user-related; a pytest captures the mocked HTTP call for every id and asserts the query equals a table entry; the table has no digits that look like dates.
- [ ] AC3 (compliance): search goes to `SEARCH_BASE_URL` (`http://egress:8083`, the search listener) with the key from env; the key, queries and results are never logged; `docker-compose.yml` publishes no host port for 8083. Checked by pytest (`caplog`), grep for logging calls in `relay/evidence.py`, and `grep -nE '(^|[^0-9])8083:' docker-compose.yml` printing nothing.
- [ ] AC4: results are cached per method id in RAM for 24 h and the top 3 are returned as `{title, url, snippet}` (snippet ≤ 300 chars); a second call within 24 h makes no outbound request. Checked by pytest counting mocked calls.
- [ ] AC5 (error-handling): provider timeout, error status or quota → generic 503 `{"error": "evidence unavailable"}`; failures are not cached. Checked by pytest.
- [ ] AC6: manual (Ved): one live call for the readiness id returns 3 sources, and mitmweb's Request body tab on the 8083 listener shows only the fixed query.
