# Story: Scenario tests

## User Story

**As an** athlete (and as a judge checking the science),
**I want** the engine to behave the way the training literature predicts in plain, recognisable situations,
**so that** I can trust it is fed and wired correctly, not just that each formula is typed right.

---

## Context

Last engine story: the 7.4 layer-3 scenario tests (DEC-22). Each builds a synthetic features JSON from a small generator and runs it through `analyze()` (or the single function named), then checks the direction the literature predicts. Unit tests (E02S01–S04) show each formula is right; these show the pieces fit together.

---

## Acceptance Criteria

- [ ] AC1: Taper: 42+ days of steady daily load, then 14 days at half load → form on the last day is higher than form on the day before the taper. Checked by `node --test "tests/**/*.test.{js,mjs}"`.
- [ ] AC2: Doubled week: 3 weeks of steady load, then 1 week at twice that load → load spike is flagged and form on the last day is lower than before that week. Checked by `node --test "tests/**/*.test.{js,mjs}"`.
- [ ] AC3: 7 identical non-zero daily loads, no rest day → monotony is flagged. Checked by `node --test "tests/**/*.test.{js,mjs}"`.
- [ ] AC4: HRV 1 SD below baseline for the whole last week (baseline ≥ 14 days) → readiness call is `easy`. Checked by `node --test "tests/**/*.test.{js,mjs}"`.
- [ ] AC5: 3 HRV readings in the last 7 days → a `hard` or `easy` call; 2 readings → `not_enough_data`. Checked by `node --test "tests/**/*.test.{js,mjs}"`.
- [ ] AC6 (compliance, PRIV-1 / SAFE-1): the generator is test-only and builds synthetic data (no real dates, names or device names); `engine.js` is not changed by this story, checked by `git diff --quiet main -- web/js/engine.js` (exit 0); and the full scoped run `node --test "tests/**/*.test.{js,mjs}"` is green.
