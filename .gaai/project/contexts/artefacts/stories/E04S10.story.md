# Story: Import progress bar and typed effort entry

## User Story

**As an** athlete,
**I want** to see how far an import has got, and to rate my effort for a workout that has none,
**so that** I know the app is working and that the session counts toward my load.

---

## Context

Added by Ved's round-1 decision R-3 (DEC-18: no feature silently dropped). Split from the original "Remaining screen items" story, which broke the caps; this is the part that needs import progress or user input. E04S08 holds the display-only items.

Two items. The import progress bar (plan 5.5: `[#########...........] 412k lines`). The typed effort entry: a workout with no effort is listed, and the athlete gives it an RPE 1–10, so its session-RPE load (DEC-8) counts. The list is the `rate_effort` gate from E02S04. Ratings are written only into the stored Features JSON (DEC-2), nothing else.

---

## Acceptance Criteria

- [ ] AC1: `web/js/view.js` exports `progressLine(lines, bytes, total)`, which returns text such as "Reading export: 412k lines" and, when `bytes` and `total` are both given, a 20-cell bar from `bar(bytes ÷ total × 100)` before it. Checked by `node --test tests/import-ui.test.js`.
- [ ] AC2: `web/js/view.js` exports a pure `onImportMessage(state, msg)` that returns the next state from one worker message: `{ progress, bytes, total }` sets the progress figure `<pre role="img" aria-label="Import progress: 412 thousand lines read, 37 percent">`, and `{ done }` or `{ error }` hides it. `web/js/app.js` paints the returned figure into its slot; E04S07 AC1 wires the real worker to it. Checked by `node --test tests/import-ui.test.js` with recorded worker messages.
- [ ] AC3: The effort list shows each stored workout whose `effort` is `null` as its sport and its age ("today", "1 day ago", "2 days ago") from the `day` offset, with ten buttons labelled 1 to 10 (`aria-label="Rate 7 of 10"`). It shows no dates. Checked by `node --test tests/effort.test.js` on the list model.
- [ ] AC4: `withEffort(features, index, rpe)` in `web/js/db.js` accepts only whole numbers from 1 to 10 (anything else returns the features unchanged and an error). For a valid rating it sets that workout's `effort`, sets its `srpe` to the engine's `srpe(effort, min)`, and recomputes the matching `days[].srpe` as the sum of that day's workout `srpe` values (`null` when none). Checked by `node --test tests/effort.test.js`.
- [ ] AC5: The main screen shows a 7-day session-RPE load line (the sum of the last 7 days' `days[].srpe`, linked to `#ref-srpe`). After a rating, the app saves with `saveFeatures()`, re-runs `analyze()`, removes the workout from the list, clears the "rate your effort" line when no unrated workouts remain, refreshes the calendar and fitness figures, and updates the session-RPE load line. Checked by `node --test tests/effort.test.js` (the line's model before and after a rating); manual (Ved): desktop browser on the E04S04 fixture.
- [ ] AC6 (compliance, PRIV-2 / FE-1): the rating is the only new value stored: `withEffort` adds no key, no timestamp and no date, and the buttons use `addEventListener` with no `on*=` attribute. Checked by `node --test tests/effort.test.js` (key set before and after) and the FE-1 greps over `web/`.

> All acceptance criteria must be verifiable. Vague criteria are invalid.

## Out of Scope

- Keeping a manual rating through a re-import (see Notes).

## Notes

- The bar is computed from `bytes` and `total` in the worker's progress messages (E03S02 AC4), not from line counts.
- A re-import replaces the stored features and so drops a manual rating. Open question for Ved: should ratings survive a re-import? Not decided here.
- Words: "rate your effort", never anything about injury or medical status (CLAIM-1).
