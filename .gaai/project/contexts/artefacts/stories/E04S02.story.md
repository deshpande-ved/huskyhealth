# Story: Rosé Pine palette and 44-column layout

## User Story

**As an** athlete on a phone,
**I want** the app in one calm dark palette that fits my screen,
**so that** the figures are readable without zooming or side-scrolling.

---

## Context

Plan 5.5 fixes the look: the Rosé Pine palette, dark only, as CSS variables; system monospace only; layouts measured in columns, about 44 on a phone. Figures get their colors from CSS classes (`z0`…`z5` for zones, plus classes for alerts, AI/voice and muted text), never from inline `style=""` attributes. E01 creates `web/css/style.css`; this story fills in the palette and the column layout.

---

## Acceptance Criteria

- [ ] AC1: `web/css/style.css` defines the ten Rosé Pine colors from the memory file once, as CSS variables in `:root`, and no hex color appears anywhere else in the file. Checked by `node --test tests/style.test.js`.
- [ ] AC2: Classes exist for every color role: `.z0` (muted, no workout), `.z1` foam, `.z2` pine, `.z3` gold, `.z4` rose, `.z5` love, plus `.alert` (love), `.ai` (iris) and `.muted` (muted), each using a variable. Checked by `node --test tests/style.test.js`.
- [ ] AC3 (compliance, FE-3 / PRIV-9): the font stack is `ui-monospace, "SF Mono", Menlo, monospace`; there is no `@font-face`, no `url(` to a font, no `@import`, and no `prefers-color-scheme: light` rule. Checked by `node --test tests/style.test.js`.
- [ ] AC4: `pre` figures are sized so 44 columns fit a 375 px wide viewport with the page's side padding, without horizontal scroll. manual (Ved): desktop browser at 375 px width, then the same check on his iPhone.
- [ ] AC5 (compliance, FE-1): no `style="` attribute in `web/**/*.html`. Checked by `grep -rn 'style="' web/ --include=*.html` returning nothing.

> All acceptance criteria must be verifiable. Vague criteria are invalid.
