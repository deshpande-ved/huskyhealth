# Story: Plan a taper for a match in N days

## User Story

**As a** squash player with a match coming up,
**I want** to type "match in N days" and get a day-by-day load plan,
**so that** I arrive fresh without losing fitness.

---

## Context

Feature F16 (feature menu, ~1.5 h). Engine and calendar half. **Cut together with E10S08** (session names from Claude); the two ship or are cut as one unit, independent of F17, F18 and F19 (DEC-18).

- Input is a count of days, never a date (PRIV-2).
- The engine decides the daily load ranges by standard tapering: cut volume ~40–60 % over the last 7–14 days, keep intensity, starting from current fitness and form (DEC-6, CLAIM-3). This runs in the browser (DEC-2). This story makes no network request.
- The plan is drawn as an ASCII calendar (DEC-20). Session names are not in this story; E10S08 adds them.
- The taper range needs a published source on its References card (FE-2). Candidate: the Bosquet et al. 2007 taper meta-analysis. **STOP:** if Delivery can't confirm the citation from a primary source, stop and report; don't invent one.

---

## Acceptance Criteria

- [ ] AC1 (error-handling): Given a day count N (1–28) and the current fitness, `taperPlan()` returns one entry per day, labelled by days before the match (1 = the day before, N = N days before). Days 1 to min(N, 14) get a load range between 40 % and 60 % of the pre-taper daily load; days further out keep the pre-taper load range unchanged (100 %). Each entry carries `source` and a version; fitness of 0 or missing returns `not_enough_data`. Checked by `node --test` with N = 1, 7, 14 and 28 (on N = 28, day 14 is tapered and day 20 is unchanged) and the no-data case.
- [ ] AC2 (compliance): entering a day count and drawing the plan makes no network request. Checked by `node --test` with a stubbed `fetch` that records calls (zero calls for N = 1, 10 and 28).
- [ ] AC3: the page has a number input for the day count (no date picker) and draws the plan as an ASCII calendar in a `<pre role="img">` whose `aria-label` holds each day's range; Plain view shows the same as text; the range links to `#ref-taper`. `web/js/taper.js` and `web/js/taper-ui.js` are added to `SHELL` in `web/sw.js` with a `CACHE` bump. Checked by `node --test` on the renderer, the FE-1 greps in `frontend.rules.md`, and a grep of `web/sw.js`.
- [ ] AC4 (compliance): the touched files contain no CLAIM-1 wording (`injury risk`, `diagnos`, `medical advice`, `treat`) in user-facing text; the copy talks about load, fitness, form and freshness. Checked by the CLAIM-1 grep on the touched files.
- [ ] AC5 (manual, Ved): on the installed PWA, "match in 10 days" draws a 10-day calendar of load ranges, and mitmweb shows no request for it.
