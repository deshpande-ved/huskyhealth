# Story: Relay answers a redacted question with narrow lookups

## User Story

**As a** player curious about my own training,
**I want** to ask a plain question and get an answer from my rounded numbers,
**so that** I understand my trends without my workouts leaving my phone.

---

## Context

Feature F17 "Ask HuskyHealth" (1.5–3 h), relay half. **Cut together with E10S03**; the two ship or are cut as one unit, independent of F16, F18 and F19 (DEC-18).

- Presidio's anonymizer strips names and places from the question first.
- The page sends up to 12 weekly summaries with the question. Each summary has a relative week index (0 = this week … 11) and only fields from the rounding table in `ai-brief-relay.md`: load (50), session-RPE load (50), session count, fitness / fatigue / form at week end (10), zone % (5), sport mix % (10). No dates, no per-workout records.
- Claude may call three lookups, which the relay evaluates over that request's data only: `weekly_trend`, `compare_periods`, `sport_breakdown`. The response lists every lookup made. Nothing is stored.
- Rules decide, AI explains (CLAIM-3): the answer explains only from the given numbers and never makes or changes the training call.
- Needs Presidio from E08 (plan: "Needs: F7, F8").
- **STOP:** if `presidio-anonymizer` won't install on the relay's `python:3.12-slim` ARM image, stop and report; don't swap in a different redactor.

## Acceptance Criteria

- [ ] AC1 (compliance): `POST /v1/ask` accepts only `AskIn` = `{v, question (≤ 280 chars), weeks (≤ 12 WeekSummary)}`, strict with `extra="forbid"` at every level; an unknown field, a date-like string in a number field, a week index outside 0–11, 13 weeks or a sport name outside the `Sport` Literal → 422 without echoing input; it needs a single-use `ask` token (replay → 410). Before building the prompt, the relay rounds each summary field with the steps in `ai-brief-relay.md` 8.3 (load and session-RPE to 50, fitness, fatigue, form and sport mix % to 10, zone % to 5). Checked by pytest: it sends unrounded values, and the mocked Claude client receives rounded ones.
- [ ] AC2 (compliance): the anonymizer replaces every `ENTITIES` hit in the question with a type tag before anything else; then `pii_types()` runs on the redacted question and on the full prompt (including lookup results). A finding in either → 422 with counts only added to `AUDIT`. A finding in Claude's answer → generic 502 with no echo. Checked by pytest: for "Is Alex's squash in Boston too much?" the mocked Claude client never receives "Alex" or "Boston", and an answer containing a planted name returns 502.
- [ ] AC3: the three lookups take a metric from a fixed list and week indexes inside the request; a bad argument returns a lookup error to Claude, not a crash; at most 4 lookup rounds, then the relay asks for a final answer. The response is `{answer, lookups: [{tool, args}]}`. Checked by pytest with a scripted mock client.
- [ ] AC4 (compliance): the system prompt says the athlete is unidentified, to explain only from the given numbers, never to make, change or override the training call (point to the call on the main screen instead), and to use training language only; the response never has a `call` field; the CLAIM-1 grep is clean on touched files. Checked by pytest asserting the prompt text and grep.
- [ ] AC5 (compliance): nothing is stored or logged: no module-level state except `AUDIT` counts; with `caplog`, a full request logs neither the question, the summaries nor the answer. Checked by pytest.
- [ ] AC6 (error-handling): a Claude or egress failure or timeout → generic 502 `{"error": "ask unavailable"}` with no echo of the question. Checked by pytest with a failing mock client.
