# Story: Remaining screen items: zone bars, load flags and gate messages

## User Story

**As an** athlete,
**I want** to see where my training time went, when my load is very even or spiking, and why a number may be less reliable,
**so that** I can read the main screen without guessing what the figures mean.

---

## Context

Added by Ved's round-1 decision R-3 (DEC-18: no feature silently dropped). Split from the original "Remaining screen items" story, which broke the caps. E04S08 covers the screen items that display data already in the Features JSON or in the engine's output: zone bars, the monotony and load-spike flags, and the other 7.4 data-gate messages beyond `NO DATA` (which E04S04 already shows). E04S10 covers the items that need input or progress from the import (import progress bar, typed effort entry).

The load-spike flag uses the threshold 1.5 from Ved's decision R-4b. Both flags are information only and use training-load wording (CLAIM-1).

---

## Acceptance Criteria

- [ ] AC1: `web/js/view.js` returns five zone-bar lines, one per Edwards zone 1–5, built with `bar()` from the 60-day `zone_min` totals, for example `z4 ######.............. 31%` (label, bar, whole-number share of all zone minutes), each line with class `z1`…`z5`. With no zone minutes it returns no bar lines and the figure reads "no heart-rate workouts yet". Checked by `node --test tests/view-items.test.js` on the E04S04 fixture.
- [ ] AC2: The monotony line appears only when `monotony.flag` is true, for example "Monotony 2.3 (info only): the last 7 days' loads are very even"; when its value is null it reads "Monotony: no variation in last 7 days (info only)" instead. The load-spike line appears only when `loadSpike.flag` is true (ratio above 1.5), for example "Load spike 1.6 (info only): last 7 days' average load is 1.6 times the 28-day average". Each links to `#ref-monotony` or `#ref-load-spike`. Checked by `node --test tests/view-items.test.js` with flags off (no line), on with a value (line and link), and on with a null value (the "no variation" line).
- [ ] AC3: The gate messages from `analyze()` (E02S04) show as plain lines, each linked to its References card: `low_confidence` → "Zones are low-confidence for N workouts: heart rate was sparse (ours)" (`#ref-zone-minutes`); `max_hr_low` → "Max HR may be underestimated: fewer than 3 sessions reached zone 4 or 5 (ours)" (`#ref-zone-minutes`); `rate_effort` → "Rate your effort for N workouts (ours)" (`#ref-srpe`). Checked by `node --test tests/view-items.test.js` with a fixture that raises each gate.
- [ ] AC4: Every row of a new `<pre role="img">` figure is 44 columns or fewer; message lines are wrapping `<p>` text and are not column-limited. Each new figure has an `aria-label` carrying its numbers (for example "Zone minutes: z1 2%, z2 11%, z3 24%, z4 40%, z5 23%"); colors come only from the `z1`–`z5` and `.alert` classes. Checked by `node --test tests/view-items.test.js` (widths, labels) and `grep -rn 'style="' web/` returning nothing.
- [ ] AC5 (compliance, CLAIM-1 / FE-1): `grep -niE "injury|diagnos|medical" web/js/view.js` returns nothing; the FE-1 greps from `frontend.rules.md` return nothing over `web/`. Checked by those greps.

> All acceptance criteria must be verifiable. Vague criteria are invalid.

## Notes

- Zone bars use the 60-day totals of `zone_min`, the same window the screen already uses. The memory file gives the bar format but not the window; the window is an assumption. If Ved wants a 7-day window, change it here.
- No new module is added. `view.js`, `app.js` and `index.html` are SHELL files, and any change to a SHELL file, including these, bumps `CACHE` (R-1).
- Whole-number percentages may not add to exactly 100.
- STOP condition: if `analyze()` does not return the gates under the names E02S04 AC3 uses (`low_confidence`, `max_hr_low`, `rate_effort`), stop and report. Do not re-derive gates in the UI (rules decide, CLAIM-3).
