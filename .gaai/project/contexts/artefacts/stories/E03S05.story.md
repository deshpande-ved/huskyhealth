# Story: Run Ved's real export locally and print counts only

## User Story

**As** the builder,
**I want** to run the parser on my own real Apple Health export on my Mac and see only counts,
**so that** I know it works on real data (and the plan's assumptions hold) without any of that data entering the repo.

---

## Context

The synthetic fixture proves the logic; a real export proves the assumptions. `scripts/apple-counts.mjs` runs the same worker import function under Node on a path given on the command line and prints counts only. It also checks the plan's open assumptions: that effort scores appear as Records (plan 6.1 spike) and that `<Record` / `<Workout` opening tags keep their attributes on one line (E03S01's scanner assumption). Real data never leaves the Mac and is never committed (SAFE-1).

---

## Acceptance Criteria

- [ ] AC1: `node scripts/apple-counts.mjs <path to export.zip or export.xml>` uses the worker's import function (no second parser) and prints only counts: lines scanned, kept samples per allowlisted type, workouts per sport, workouts per normalized source, workouts with user effort / estimated effort / none, `hr_sample_ok` true / false counts, days with HRV, workouts deduped, and opening tags whose attributes continue on the next line. Check: run against `tests/fixtures/synthetic-export.xml` and a zip the test writes to `os.tmpdir()` (never into the repo; no in-memory zip for the CLI) in `node --test tests/apple-counts.test.js`; output matches the fixture's known counts; `web/sw.js` CACHE bumped; `node --test tests/web-sw.test.js` green.
- [ ] AC2 (compliance, SAFE-1 / PRIV-2): the output contains no dates, timestamps, device or source names, or values; the script writes no files. Check: `tests/apple-counts.test.js` asserts the fixture run's stdout has no date pattern and none of the fixture's device names, and the working tree is unchanged after the run. Also run the PRIV-1 grep (`grep -nE "fetch\(|XMLHttpRequest|WebSocket|EventSource|sendBeacon|importScripts|import\(['\"]https?:|from ['\"]https?:" web/js/parse-apple.worker.js scripts/apple-counts.mjs`) and require it to return nothing.
- [ ] AC3 (compliance, SAFE-1): the script refuses a path inside the repository working tree (prints "keep real exports outside the repo" and exits non-zero), except files under `tests/fixtures/` that start with `synthetic-`. Check: `tests/apple-counts.test.js`.
- [ ] AC4 (error-handling): no argument, a missing file, or a zip without `export.xml` (written by the test to `os.tmpdir()`, never into the repo) prints a one-line usage or error and exits non-zero. Check: `tests/apple-counts.test.js`.
- [ ] AC5: manual (Ved): run the script on his real export from outside the repo; it finishes and prints plausible counts; `git status --porcelain` afterwards shows nothing new. Delivery supplies the exact paste-ready command and does not claim this passed.
- [ ] AC6: manual (Ved): from that run, report (a) whether effort-score Records were found (plan 6.1 spike) and (b) whether the split-attribute tag count is 0. If either is not as the plan assumes, or every workout is `hr_sample_ok` false or every workout is "Other app", STOP and report to Discovery; don't work around it. If Ved has Garmin-synced workouts and the Garmin count is 0, STOP and report to Discovery.

> All acceptance criteria must be verifiable. Vague criteria are invalid.
