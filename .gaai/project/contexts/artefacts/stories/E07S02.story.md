# Story: Read-aloud with captions, and phone voice

## User Story

**As an** athlete looking at my brief,
**I want** to hear it read aloud with each word highlighted, or read by my phone's own voice,
**so that** I can follow along, and I choose whether the text goes to Gradium at all.

---

## Context

Under the brief, two buttons: **Read it aloud** (Gradium, through `/v1/speak`) and **Use phone voice** (`speechSynthesis`, on-device, works in airplane mode). Gradium is a separate provider from Claude, so it needs its own second consent (PRIV-5) showing exactly what Gradium will get: the brief text, word for word. Captions highlight each word as it is spoken, driven by the word timings E07S01 found in Gradium's response.

H-3 (unverified): Gradium returns word timings. If E07S01 reported that it does not, stop and report before building captions. The expected fallback (for Ved to confirm) is estimated timing, visibly labelled "estimated".

---

## Acceptance Criteria

- [ ] AC1 (compliance): the first tap on **Read it aloud** opens a Gradium-only consent that shows the exact brief text to be sent; nothing is sent until the user agrees; consent is stored as `gradium_consent` (default false, cleared by Forget) in the `db.js` settings store (E05S08) and can be withdrawn from a control next to **Read it aloud**; Claude consent does not imply Gradium consent. Check: `node --test` asserts no `/v1/speak` request without Gradium consent.
- [ ] AC2: after consent, the PWA posts the exact text with the speak token and plays the audio from a `blob:` URL (allowed by `media-src 'self' blob:`). Check: `node --test` with `fetch` mocked asserts the body is `{text}` equal to the brief and the `Authorization` header uses the speak token.
- [ ] AC3: captions highlight each word as it is spoken, from Gradium's word timings, the full text stays static in a non-live element and only the highlight moves (no `aria-live` on the highlight); if timings are estimated (H-3 fallback, only after Ved confirms), the caption shows "estimated". Check: `node --test` on the pure function mapping playback time to the current word index.
- [ ] AC4 (compliance): **Use phone voice** reads the same text with `speechSynthesis` and makes no network request. Check: `node --test` with `fetch` and `XMLHttpRequest` stubbed to fail asserts neither is called; manual (Ved): it speaks on the iPhone in airplane mode.
- [ ] AC5 (error-handling): if `/v1/speak` fails (410, 429, 502 or offline), the PWA shows a short plain message and offers **Use phone voice**; it never retries with the same token. Check: `node --test` with mocked failures.
- [ ] AC6: FE-1 holds for the new code: `grep -rnE "innerHTML|outerHTML|insertAdjacentHTML|document\.write" web/` returns nothing; `grep -rnE " on[a-z]+=|style=\"" web/ --include=*.html` returns nothing. Every new file the app needs offline (`web/js/voice.js` and `web/js/captions.js`) is in `SHELL` in `web/sw.js`, and `CACHE` is bumped (R-1). Check: those greps and `node --test tests/web-sw.test.js`.

> All acceptance criteria must be verifiable. Vague criteria are invalid.
