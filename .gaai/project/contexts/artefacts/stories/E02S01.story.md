# Story: Zone minutes, TRIMP and session-RPE

## User Story

**As an** athlete,
**I want** each workout's heart-rate zone minutes, TRIMP load and session-RPE load worked out on my phone with published methods,
**so that** I can trust my session load and see where each number comes from.

---

## Context

First story of the engine (F4). It creates `web/js/engine.js` and the test setup the rest of E02 builds on:
- the per-session rows of the 7.1 table: zone minutes and TRIMP (Edwards 1993), session-RPE (Foster et al. 2001, DEC-8);
- the source table (FE-2): one entry per 7.1 row, so every later output can carry `source`;
- a small adapter that turns the features JSON (6.5, `v: 1`) into day-by-day arrays, oldest to today;
- the purity check (PRIV-1): no DOM, no network, no imports;
- the root `package.json` (R-4d) that every later epic's tests use, and the offline shell entry for `engine.js` (R-1).

The 7.2 sketch in the engine memory file is the starting point. It has one known bug to fix: `Math.floor((pct - 0.5) * 10)` puts exactly 60 % of max HR in zone 1 because of floating point (0.6 − 0.5 = 0.0999…). Zone lower bounds are inclusive.

---

## Acceptance Criteria

- [ ] AC1: `zoneMinutes(hr, start, end, maxHr)` passes hand-worked tests (worked numbers in comments): samples below 50 % add nothing; sample gaps are capped at 1 minute; samples outside the window are ignored; samples at exactly 60, 70, 80 and 90 % of max HR go to the higher zone; ≥ 100 % goes to zone 5. Example anchor: max 200, samples `[0,100] [60000,130] [120000,150] [300000,190] [360000,210]` → `[1,1,1,0,1]`. Checked by `node --test "tests/**/*.test.{js,mjs}"`.
- [ ] AC2: `trimp([3,11,21,18,7])` is 195 (weights 1…5) and `srpe(7, 60)` is 420; `srpe` returns `null` when effort is missing. Checked by `node --test "tests/**/*.test.{js,mjs}"`.
- [ ] AC3 (compliance, FE-2 / DEC-6): `engine.js` exports `VERSION` and `SOURCES` with one entry per 7.1 row, ids `zone-minutes, trimp, srpe, fitness-fatigue, monotony, readiness, data-check, baseline, load-spike, vo2-trend, sport-view`; each entry has `method`, `citation`, `status` (one of `published`, `adapted`, `ours`, `disputed`, `descriptive`, matching 7.1) and `version`. A helper attaches `source` to output values; zone minutes, TRIMP and session-RPE results carry it. Checked by `node --test "tests/**/*.test.{js,mjs}"`.
- [ ] AC4: `dailySeries(features, key, fill)` returns an array of `window_days` values for day offsets `-(window_days-1)…0`, oldest first, using `fill` for missing days; it throws on a features JSON whose `v` is not 1. Checked by `node --test "tests/**/*.test.{js,mjs}"` with a hand-written synthetic features object.
- [ ] AC5 (compliance, PRIV-1 / DEC-2): `engine.js` has no DOM, no network and no imports: `grep -nE "\b(document|window|navigator|localStorage|sessionStorage|indexedDB)\.|fetch\(|XMLHttpRequest|WebSocket|EventSource|sendBeacon|^\s*import\b|import\(" web/js/engine.js` returns nothing, and `tests/engine/purity.test.mjs` asserts the same. `node --test "tests/**/*.test.{js,mjs}"` run from the repo root (picking up `tests/engine/*.test.mjs`) is green. Checked by `node --test "tests/**/*.test.{js,mjs}"` and the grep.
- [ ] AC6: Root `package.json` has `"type": "module"` and `"scripts": {"test": "node --test \"tests/**/*.test.{js,mjs}\""}` (R-4d). `web/sw.js` adds `/js/engine.js` to `SHELL` and bumps `CACHE` to the next version, so the offline install still works. Checked by `grep -n '"/js/engine.js"' web/sw.js` and `node --test tests/web-sw.test.js` (E01S03 file, modified here to expect `/js/engine.js` in `SHELL` and the `CACHE` pattern), both within the scoped run `node --test "tests/**/*.test.{js,mjs}"`.

## Notes

- Ved decision R-4d: this story creates the root `package.json`; other epics reuse it. No bundler, no build step.
- STOP condition: if Node can't load `web/js/engine.js` as an ES module (needs Node ≥ 22.7 module detection), stop and report; don't add a bundler or a build step to work around it.
- Same inputs, same outputs: no `Date.now()`, no randomness in `engine.js`.
- Source ids are exactly `zone-minutes`, `trimp`, `srpe`, `fitness-fatigue`, `monotony`, `readiness`, `data-check`, `baseline`, `load-spike`, `vo2-trend`, `sport-view` (AC3). Cards link as `#ref-<id>`. Don't rename them later without Discovery.
- Test fixtures are synthetic only (SAFE-1).
- Wording in `SOURCES` uses training language only (CLAIM-1): the load spike entry says "info only", never "injury risk".
