# Story: Taper session names from Claude

## User Story

**As a** squash player with a match coming up,
**I want** a named squash session for each day of my taper,
**so that** I know what to do each day without changing my load.

---

## Context

Feature F16 (feature menu), Claude half. **Cut together with E10S01**; the two ship or are cut as one unit, independent of F17, F18 and F19 (DEC-18).

- Claude sees only: days to match (a count), form (rounded to 10) and sport mix (% rounded to 10, keyed by the `Sport` Literal in `relay/schema.py`). It names one session per day from a fixed list: ghosting, court sprints, solo drills, rest, match. It never sets or changes a load range; the ranges come from E10S01's `taperPlan()`.
- The relay rounds form and sport mix with the steps in `ai-brief-relay.md` 8.3 before it builds the prompt, whatever the page sent.
- The route uses a single-use `taper` token; the prompt and Claude's reply go through `pii_types()` (PRIV-8). The relay token route itself comes from E05S02, used through E05S03.
- The page merges the session names into the ranges it already has; the relay never sees the ranges.

---

## Acceptance Criteria

- [ ] AC1 (compliance): `POST /v1/taper` accepts only `TaperIn` = `{v, days, form, sport_mix}` (strict, `extra="forbid"`); `sport_mix` keys must come from the `Sport` Literal; a date string, an unknown field, an unknown sport or `days` outside 1–28 → 422 without echoing input; it needs a single-use `taper` token (replay → 410). Checked by pytest.
- [ ] AC2 (compliance): before building the prompt the relay rounds `form` and each `sport_mix` value to 10 with the step in `ai-brief-relay.md` 8.3; `pii_types()` runs on the prompt and on Claude's reply, and any finding → 422 with counts only added to `AUDIT`. Checked by pytest: it sends unrounded values, and the mocked Claude client receives rounded ones.
- [ ] AC3 (compliance): the system prompt says the athlete is unidentified, that the load ranges are already decided and must not change, and to use training language only; nothing is logged but counts. Checked by pytest asserting the prompt text and with `caplog`, and the CLAIM-1 grep clean on touched files.
- [ ] AC4 (error-handling): the relay validates Claude's reply as exactly one session per day from the fixed list, plus an optional note of ≤ 80 characters that contains no digit. A wrong day count, an unknown session or a note with any digit → generic 502 with no echo. The page then shows the engine ranges alone with "Session ideas unavailable". Checked by pytest with a mocked Claude client and `node --test` with a stubbed `fetch`.
- [ ] AC5 (compliance): the page shows the exact `TaperIn` JSON and asks for Claude consent before sending (PRIV-5); without consent no request is made; after a reply the calendar shows each day's session beside its range (the `<pre>` `aria-label` holds both). Checked by `node --test` with a stubbed `fetch` that records calls.
- [ ] AC6 (manual, Ved): on the installed PWA, "match in 10 days" shows a session name for each day; mitmweb's Request body tab for the Claude call shows only `days`, `form` and `sport_mix`.
