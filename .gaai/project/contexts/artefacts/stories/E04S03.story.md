# Story: References page with a card per method

## User Story

**As an** athlete, coach or judge,
**I want** one card for each method behind HuskyHealth's numbers,
**so that** I can check what each number measures, its formula and its source.

---

## Context

DEC-6 and FE-2 say every number cites a published source or is labeled as ours. Plan 7.3 asks for a References page in the app: one card per row of the 7.1 table (11 rows), each with what it measures, the formula in one line, the citation, and its status (published, adapted, ours, disputed or descriptive), plus plain-word caveats. The main screen (E04S04) links each metric to its card by anchor, so card ids are fixed here.

---

## Acceptance Criteria

- [ ] AC1: The References page has exactly 11 cards, one per 7.1 row, with these ids: `ref-zone-minutes`, `ref-trimp`, `ref-srpe`, `ref-fitness-fatigue`, `ref-monotony`, `ref-readiness`, `ref-data-check`, `ref-baseline`, `ref-load-spike`, `ref-vo2-trend`, `ref-sport-view`. Checked by `node --test tests/references.test.js` (reads `web/index.html`).
- [ ] AC2: Each card shows what it measures, a one-line formula, the citation from 7.1, and a status of exactly one of `published`, `adapted`, `ours`, `disputed` or `descriptive`, matching 7.1 (readiness is `adapted`; baseline length and sport view are `ours`; load spike is `disputed` and says "info only"; VO2 max trend is `descriptive`). Checked by `node --test tests/references.test.js`.
- [ ] AC3: The page shows the four caveats from 7.3: SDNN vs. morning rMSSD; max HR is observed, not tested; Garmin-only users have no HRV; "training insight, not medical advice". Checked by `node --test tests/references.test.js`.
- [ ] AC4: The page is reachable from the main screen and from each card's anchor (`#ref-<id>`) while offline, with no new network request. Checked by: cards are static HTML in an already-cached page, confirmed by `grep -c 'id="ref-' web/index.html` = 11; manual (Ved): open a card link on the installed PWA in airplane mode.
- [ ] AC5 (compliance, CLAIM-1 / CLAIM-2 / FE-1): `grep -rniE "injury risk|diagnos|treat(s|ment)?\b|anonymous|anonymi[sz]" web/` returns nothing; `grep -rni "medical advice" web/` returns only the "training insight, not medical advice" disclaimer; no `innerHTML`, inline script or `style=""` added (FE-1 greps in `frontend.rules.md` return nothing).

> All acceptance criteria must be verifiable. Vague criteria are invalid.
