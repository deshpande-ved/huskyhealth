# Story: Show the GoldenCheetah correlation on the References page

## User Story

**As** an athlete or a judge reading the References page,
**I want** to see how closely HuskyHealth's fitness and fatigue match GoldenCheetah's on the same files,
**so that** I can trust that the published formulas are implemented correctly.

---

## Context

Plan 7.4 layer 2: "report correlation on References". The number comes from Ved's manual run (E09S04, T-1). This story adds a small data module Ved edits (`web/js/validation.js`) and a References card that shows it. Until Ved fills it in, the card says the cross-check has not been run; it never shows a made-up number. The card also credits the Garmin FIT SDK and names GoldenCheetah as the reference tool (plan 7.4 eligibility: libraries credited).

---

## Acceptance Criteria

- [ ] AC1: `web/js/validation.js` exports one object with `fitness_vs_ctl_r`, `fatigue_vs_atl_r`, `days`, `gc_version`, all `null` by default. `validation.js` and `validation-card.js` are added to `sw.js` `SHELL` and the cache version is bumped. Checked by: `node --test tests/validation-card.test.js`, which reads `web/sw.js` and asserts both files are in `SHELL` and the cache version is higher than the E01S03 value recorded in that test.
- [ ] AC2: `web/js/validation-card.js` exports a pure `cardLines(v)`. With values set, its lines show both r values to 2 decimals, the day count, the GoldenCheetah version and the method line "TRIMP Zonal Points, HR zones at 50–90 % of the same max HR". `renderCard(el)` fills the container. Checked by: `node --test tests/validation-card.test.js` on `cardLines(v)`.
- [ ] AC3 (error-handling): In `cardLines(v)`, with `null`, missing, non-numeric or out-of-range (outside −1…1) values, the card says "Cross-check not run yet" and shows no number. Checked by: `node --test tests/validation-card.test.js`.
- [ ] AC4 (compliance, FE-1/FE-2): `web/index.html` holds only one empty container with id `ref-gc-crosscheck`; `renderCard(el)` builds the card with `createElement`/`textContent`, labels it as our own validation, and credits "Garmin FIT SDK (Garmin's FIT licence)" and "GoldenCheetah (GPL v2, used as a separate tool; no code included)". Checked by: `node --test tests/references.test.js`, which asserts the References page has 11 method cards plus `ref-gc-crosscheck`; and `grep -rnE "innerHTML|outerHTML|insertAdjacentHTML|document\.write" web/` returns nothing.
- [ ] AC5 (compliance, CLAIM-1/2): The wording in `web/js/validation.js` and `web/js/validation-card.js` describes agreement with GoldenCheetah only, not accuracy, health or injury. Checked by: `grep -niE "injury risk|diagnos|medical|anonymous|proves|accurate" web/js/validation.js web/js/validation-card.js` returns nothing user-facing, except the one exempt disclaimer line "training insight, not medical advice" (R-4e).
- [ ] AC6: manual (Ved): after his GoldenCheetah run (E09S04), he pastes the r values into `validation.js`, deploys, and sees them on the References page.

> All acceptance criteria must be verifiable. Vague criteria are invalid.
