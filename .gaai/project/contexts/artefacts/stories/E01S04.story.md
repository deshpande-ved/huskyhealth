# Story: `_headers` with the CSP

## User Story

**As an** athlete,
**I want** the app to be technically unable to send data anywhere except its own site and the relay,
**so that** the privacy promise holds even if a bug or a bad script tries otherwise.

---

## Context

Cloudflare Pages applies `web/_headers` to every response (DEC-19). The CSP there is the egress lock: `connect-src` allows only `'self'` and the relay origin (DEC-10, PRIV-9). The text in `infra-deploy.md` is the spec, byte for byte.

---

## Acceptance Criteria

- [ ] AC1: (compliance, PRIV-9) `web/_headers` is exactly the block in `infra-deploy.md` § "`web/_headers`": the `/*` rule with `Content-Security-Policy`, `Permissions-Policy`, `Referrer-Policy`, `X-Content-Type-Options`; `/sw.js` with `Cache-Control: no-cache`; `/manifest.webmanifest` with `Content-Type: application/manifest+json`. Checked by `node --test tests/web-headers.test.js` comparing the file to the expected text inlined in the test.
- [ ] AC2: (compliance) the CSP's `connect-src` is exactly `'self' https://veds-pi5.polecat-nominal.ts.net:10000`, and `script-src`, `style-src`, `worker-src` are `'self'` only (no `'unsafe-inline'`, no `'unsafe-eval'`, no other host). Checked by the same test.
- [ ] AC3: The file uses two-space indentation under each path and LF line endings, as Pages expects. Checked by the same test.

> All acceptance criteria must be verifiable. Vague criteria are invalid.
