# Story: Relay turns a short voice clip into one effort number

## User Story

**As an** athlete who turned voice check-ins on,
**I want** to say my effort ("seven") and get back just the number 7,
**so that** squash sessions get an effort score, and nothing else about my voice survives.

---

## Context

`POST /v1/listen` takes ≤ 5 s of audio (≤ 200 KB) with a `Bearer` listen token from `/v1/token?kind=listen`. The relay sends the audio to Gradium speech-to-text through `GRADIUM_BASE_URL` (`egress:8082`), reduces the transcript to one integer 1–10, and returns only `{effort: n}`. Audio and transcript are discarded and never logged.

Split note: runbook story 4 is cut into this story (relay) and E07S05 (PWA), to fit the caps. Cut together with E07S05.

H-2 (unverified): Gradium STT returns a transcript the relay can reduce to an integer 1–10 without logging it. If the API reference shows otherwise (for example only a streaming transcript the relay can't hold in memory, or transcripts kept server-side with no opt-out), stop and report; don't work around it.

## Acceptance Criteria

- [ ] AC1: Delivery reads the transcription section of Gradium's official API reference and adds to the header of `relay/gradium.py`: the doc URL, the STT path, the request body/audio format, and the response field holding the transcript. Nothing is guessed. If H-2 doesn't hold, stop and report. Check: `grep -n "docs.gradium.ai" relay/gradium.py`; reviewer compares against the reference.
- [ ] AC2: a pure `effort_from_transcript()` returns an integer 1–10 or `None`: "seven" → 7, "7" → 7, "it was a seven" → 7, "seven out of ten" → 7, "ten" → 10, "eleven", "zero", "seven or eight", "" → `None`. Check: pytest table test.
- [ ] AC3: with a valid listen token and audio ≤ 200 KB, `/v1/listen` returns exactly `{"effort": n}` and no other key; the transcript never appears in the response. Check: pytest with Gradium mocked asserts the JSON keys equal `{"effort"}`.
- [ ] AC4 (error-handling): reused or wrong-kind token → 410; body over 200 KB → 413 without calling Gradium; no number found → 422 `{"error": "no effort heard"}`; Gradium failing → 502 generic. Check: pytest.
- [ ] AC5: an hourly limit on `/v1/listen` using the shared limiter from E07S01 (`LISTEN_LIMIT_PER_HOUR`, default 60): the request over the limit → 429 and Gradium is not called. Check: pytest with a fake clock.
- [ ] AC6 (compliance): audio bytes and transcripts are never logged or written to disk on any path (success, 410, 413, 422, 429, 502). Check: pytest captures all log output (caplog and capsys) and asserts neither the audio bytes nor the mocked transcript appear; the PRIV-6 grep returns nothing. The body is read with `request.get_data()` (raw bytes, not multipart), and the listen path (`/v1/listen`, `relay/gradium.py`, `relay/effort.py`) has no `tempfile`, `.save(` or `open(` (grep).

> All acceptance criteria must be verifiable. Vague criteria are invalid.
