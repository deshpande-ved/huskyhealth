# Story: Compose stack with a /v1-only gateway and a read-only relay

## User Story

**As** Ved, running the relay,
**I want** one `docker compose up` to start the gateway, the relay and the egress proxy with the relay locked down,
**so that** the relay can only be reached under `/v1/`, only from our own web origins, and can only reach the internet through the proxy.

---

## Context

Three containers: `gateway` (nginx), `relay` (gunicorn, one worker), `egress` (mitmweb). The compose file, nginx config with the CORS map, and relay Dockerfile are given in the memory source; this story writes them and two check scripts. Ports: gateway `127.0.0.1:8090`, mitmweb UI `127.0.0.1:8091`, relay `8000` internal, egress listeners `8080` (Claude) and `8082` (Gradium) internal.

---

## Acceptance Criteria

- [ ] AC1: Given a hand-made `.env` from `.env.example`, when `docker compose up -d --build` runs on the Mac, then all three services are running and `scripts/check-gateway.sh http://127.0.0.1:8090` reports `GET /v1/healthz` → 200 `ok`.
- [ ] AC2 [error-handling]: The gateway serves only `/v1/`: `scripts/check-gateway.sh` asserts `/`, `/healthz` and `/anything` → 404, and `OPTIONS /v1/brief` → 204 with `Cache-Control: no-store`.
- [ ] AC3 [compliance]: CORS allows exactly the map's origins: `scripts/check-gateway.sh` asserts `Access-Control-Allow-Origin` echoes `https://huskyhealth.vedsite.com`, `https://huskyhealth.pages.dev` and `https://feat-x.huskyhealth.pages.dev`, and is absent for `https://evil.example`, `https://huskyhealth.pages.dev.evil.example`, `http://huskyhealth.pages.dev` and `null`. The script takes the base URL as its only argument so E05S06 can run it against the public URL.
- [ ] AC4 [compliance]: The relay is read-only with no volumes and one worker: `scripts/check-relay-container.sh` prints `readonly=true mounts=0 workers=1 caps=none` from `docker inspect`, `docker compose top relay` run from the host shows the gunicorn master plus one worker (2 processes), and the relay is attached only to the `internal` network. PRIV-6: `grep -q "access_log off" nginx/default.conf` and `grep -q 'X-Forwarded-For ""' nginx/default.conf` both pass.
- [ ] AC5 [compliance]: The relay reaches the internet only through egress: `docker compose exec relay python -c "import urllib.request; urllib.request.urlopen('https://api.anthropic.com', timeout=5)"` fails, and `egress:8080` resolves from the relay. Checked by `scripts/check-relay-container.sh`.
- [ ] AC6 [compliance]: SAFE-1/5: `.env.example` has only empty values for `ANTHROPIC_API_KEY`, `GRADIUM_API_KEY` and `GRADIUM_VOICE_ID`; `git check-ignore .env` succeeds; `grep -rnE "sk-ant-[A-Za-z0-9_-]{20,}" relay nginx egress scripts docker-compose.yml .env.example` returns nothing; only `127.0.0.1:8090` and `127.0.0.1:8091` are published (`docker compose port`).

## Notes

- Copy `docker-compose.yml` and `nginx/default.conf` from the memory source. Two changes only, both from the memory notes: `egress` uses `build: ./egress` (a `python:3.12-slim` image with `pip install "mitmproxy>=10"`, since there is no ARM mitmproxy image), and the relay Dockerfile omits the spaCy line until E08.
- STOP: if mitmweb in the built image rejects two `--mode reverse:` listeners, stop and report; do not drop the Gradium listener or add a second egress container on your own.
- Gunicorn: `--workers 1 --threads 8`, no `--access-logfile` (PRIV-6, PRIV-7). nginx keeps `access_log off` and blanks `X-Forwarded-For` and `Forwarded`.
- SAFE-3: `docker compose down` is fine; never `docker system prune` or `rm -rf` without asking Ved.
- mitmweb's login token is in `docker compose logs egress`; never paste it into an artefact.
