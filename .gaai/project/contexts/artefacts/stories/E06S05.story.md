# Story: Turn-off flow and demo

## User Story

**As an** athlete who tried convenience mode,
**I want** turning it off to delete my keys and make the relay forget my box,
**so that** nothing about me stays on the Pi, and judges can watch the whole flow work.

---

## Context

Plan 5.4, "Turning it off": the app deletes its keys and calls `DELETE /v1/box/<box>` (read secret); the relay forgets the box. PRIV-4 also requires the mode to be OFF after **Forget everything**. The demo script is the headline moment: finish a workout → open Messages → HuskyHealth shows it.

---

## Acceptance Criteria

- [ ] AC1 (compliance): turning the toggle off (after a one-line confirm) calls `DELETE /v1/box/<box>` with the read secret, deletes the key pair, box ID and read secret from IndexedDB, and shows the toggle OFF. Checked by `node --test` with a stubbed `fetch` and in-memory IndexedDB, and by a grep showing `CACHE` in `web/sw.js` is bumped (R-1).
- [ ] AC2 (error-handling): if the DELETE fails (offline, 404, 5xx), the local keys are still deleted, the toggle is OFF, and a plain status line says any pending drop on the Pi expires within 24 hours and can no longer be opened. Checked by `node --test`.
- [ ] AC3 (compliance, PRIV-4): **Forget everything** runs the same turn-off flow, so afterwards the mode is OFF, the sync store is empty, and the next app open makes no sync call. `unpair()` reads the read secret before Forget deletes the database, so the DELETE call still goes out. Checked by `node --test`.
- [ ] AC4: `docs/demo-sync.md` gives the demo script step by step: mode OFF by default, pair (off camera: pairing shows the write secret, SAFE-5), finish a workout, open Messages, open HuskyHealth and see the new workout, turn off. It is public-safe (only the public relay origin, no secrets, no keys on screen; pairing happens off camera per SAFE-5); `grep -nE "([0-9]{1,3}\.){3}[0-9]{1,3}|ssh " docs/demo-sync.md` returns nothing.
- [ ] AC5 (compliance, PRIV-2): `relay/tools/dump_boxes.py` runs the create → drop flow in-process through the Flask test client, on synthetic data, and prints one line per box: the ciphertext length and the first 16 hex bytes of `ct`. It prints no plaintext and no key material. A pytest asserts the dump has the length and a 32-character hex head, and that a unique plaintext marker appears nowhere in the output. mitmweb stays the egress proof for Claude and Gradium only (R-4f); Delivery doesn't route drop traffic through it.
- [ ] AC6: manual (Ved): Ved runs the live demo from `docs/demo-sync.md` on his iPhone end to end, including turn-off and the AC5 dump, after which a `curl` GET on the old box returns 404.

## Notes

- The box itself has no expiry in the spec; after a failed DELETE it lives until the relay restarts, holding only a public key. Without the phone's private key any later drop is unreadable, and drops expire in 24 h.
- `BOXES` lives in the gunicorn worker's RAM, so a separate process sees an empty dict. The dump therefore runs in-process through the Flask test client. Ved decided (2026-11-07): the in-process dump is enough; no debug route is ever added to the live relay.
- Use "de-identified", never "anonymous", in UI and docs (CLAIM-2).
